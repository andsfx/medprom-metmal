# PLAN 2026-09-24 11:11 WIB - Simpan persetujuan ketentuan apa adanya pada pengajuan cetak batch

## Latar cacat (T5, kepercayaan data)

Handler `POST /promo/submit-batch` (`server/src/routes/promo.js`) menuliskan
nilai **KONSTANTA `true`** ke kolom `terms_accepted` untuk setiap baris
`promo_submissions` pada array `row` di dalam `itemRows.forEach`, dan **tidak
pernah membaca** `body.terms_accepted`. Akibatnya kolom `terms_accepted` pada
alur cetak tidak membuktikan persetujuan apa pun; pemanggilan API langsung bisa
melewatinya.

Bandingkan dengan alur digital `POST /promo/submit` di berkas yang sama, yang
memang menegakkan:

- `server/src/routes/promo.js:333` -
  `const termsAccepted = body.terms_accepted === true;`
- `server/src/routes/promo.js:355` -
  `if (!termsAccepted) errors.push('Persetujuan ketentuan wajib dicentang');`

Di FE, wizard cetak (`src/components/promo/PromoCetakWizard.tsx`) sudah
menggerbang tombol kirim pada state `termsAccepted` (`:382-385`, `:933`), tetapi
`BatchSubmitPayload` (`src/utils/promoApi.ts`) tidak memuat field itu sehingga
tidak pernah dikirim.

## Penegakan 400 ditunda (keputusan pemilik)

Menambahkan `if (!termsAccepted) errors.push('Persetujuan ketentuan wajib
dicentang');` pada `/submit-batch` akan memecahkan fixture batch LAMA:

- `__tests__/api/promo-batch.test.js` - `BASE` tidak memuat `terms_accepted` dan
  mengharapkan 201/429;
- `__tests__/api/cetak-batch-limits.test.js` - `BASE` juga tidak memuatnya dan
  mengharapkan 201.

Karena aturan repo melarang menyunting test lama tanpa izin pemilik, penegakan
400 **belum dipasang**. Perubahan ini berhenti pada menghapus nilai hardcoded
`true`: kolom kini menyimpan isi body apa adanya (`false` bila field tidak
dikirim), sehingga penegakan bisa ditambahkan belakangan tanpa mengubah makna
kolom. **Test lama TIDAK tersentuh.**

sungguhan, pola mock sama dengan `promo-batch.test.js`: mock `db.js`, `drive.js`,
