# Audit UI/UX — medprom-metmal (2026-09-30 15:41 WIB)

**Jenis:** audit kesesuaian standar. Temuan diukur lebih dulu (read-only), lalu
perbaikan **di dalam repo** dikerjakan untuk semua temuan yang tidak butuh
akses eksternal (M1, M2, L1, L2, L3, dan jalur UX dari H1). Yang tetap terbuka:
C1/C1b (butuh akses Vercel + VPS) dan langkah **konfigurasi** H1 (butuh akses
dashboard Cloudflare) — lihat "Perbaikan selama pengerjaan".
**Skill:** `ui-ux-pro-max` (10 kategori prioritas, 119 panduan UX).
**Alat ukur:** axe-core 4.10.2 (`wcag2a`/`2aa`/`21a`/`21aa`/`22aa`/`best-practice`),
pengukuran DOM langsung (kontras efektif, target sentuh, luber horizontal,
trap fokus, `prefers-reduced-motion`), plus pembacaan sumber.

## Tujuan

Menjawab satu pertanyaan: **apakah UI/UX proyek ini sudah sesuai standar?**
Standar yang dipakai = tabel prioritas 1–10 skill `ui-ux-pro-max` (Accessibility →
Touch → Performance → Style → Layout → Tipografi/Warna → Animasi → Form →
Navigasi → Chart), bukan vonis redesign. Hasil `--design-system` (yang
menyarankan Glassmorphism/dark) **tidak** dipakai sebagai target: proyek punya
arah visual sendiri yang terkunci di `DESIGN.md`.

## Metode & cakupan

Dua permukaan diukur: **produksi** `medprom-metmal.vercel.app` (data nyata,
API `promapi.metmalcommunityspace.web.id`) dan **lokal** `localhost:5173`
(katalog gagal termuat — tanpa `DATABASE_URL`, jadi hanya menutup state galat).

Matriks: 10 rute × 4 viewport (320/375/768/1440) → ±64 kombinasi rute×viewport
dengan axe + pengukuran luber. Rute: `/`, `/ajukan`, `/ajukan-cetak`,
`/riwayat`, `/lacak`, `/login`, `/admin`, `/status/:token`, `/batch/:token`,
rute tak dikenal. Permukaan ber-sesi (konsol staf + Sheet detail) diukur
setelah login.

## CRITICAL

### C1. `/login` produksi membocorkan kredensial staf yang benar-benar berlaku

Halaman `/login` produksi menampilkan panel **"Akun demo (tahap pengembangan)"**
yang mencetak tiga email staf nyata beserta password seragam `admin123`.
Diverifikasi: mengisi `super@metmal.co.id` / `admin123` → **berhasil masuk
sebagai `superadmin`** dan konsol staf memuat data pengajuan tenant nyata
(2 pengajuan: Chatime, Optik Melawai).

Bukti: `document.body.innerText` produksi memuat
`"Akun demo (tahap pengembangan) … Password semua akun: admin123"`,
lalu `page.url()` berpindah ke `/admin` dengan peran `superadmin`.

Sumber: `src/constants/devCredentials.ts` (`DEV_ACCOUNTS`,
`DEV_LOGIN_PASSWORD = 'admin123'`), dirender `AdminLoginPage.tsx:116,125,129`
di balik `isDevLoginHintEnabled()` yang **menyala secara bawaan** dan hanya mati
bila `VITE_PROMO_SHOW_DEV_LOGIN === '0'`. Flag itu belum diset `'0'` saat build
produksi.

Dampak: siapa pun yang membuka `/login` mendapat akses **superadmin** —
termasuk hapus pengajuan, kelola akun, dan seluruh data tenant. Ini bukan
kebocoran teoretis; kredensialnya berlaku.

Perbaikan (butuh keputusan + akses, tidak bisa dikerjakan dari repo saja):
1. Set `VITE_PROMO_SHOW_DEV_LOGIN='0'` di env build Vercel **lalu redeploy**
   (nilai `VITE_*` di-inline saat build — mengubah env saja tidak cukup).
2. Reset password ketiga akun nyata (`server/scripts/create-admin.mjs --reset`).
3. Sadari bahwa flag hanya menggerbangi perenderan — kredensialnya tetap ada di
   bundle (`AGENTS.md` pitfall #13). Setelah password direset, sisa bundle tidak
   lagi berbahaya.

### C1b. Efek lanjutan: `/login` tanpa pembatas laju

Terkait C1 — `/api/v1/auth/login` tidak punya `enforceRateLimit` (tidak seperti
`/promo/*`). Dengan password default yang dipublikasikan di halaman itu sendiri,
ini melengkapi jalur masuk yang sepenuhnya terbuka. Perbaikan: batasi laju
`/auth/login` per IP.

## HIGH

### H1. `/lacak` tidak bisa dipakai: captcha `110200`, tombol terkunci permanen

Widget Turnstile **tidak pernah terbit** di produksi. Konsol:
`[Cloudflare Turnstile] Error: 110200.` Akibatnya `captchaToken` selalu `''`,
`captchaBlocked` selalu `true`, dan tombol **Lacak** `disabled` selamanya.

Bukti terukur di produksi: `input[name='cf-turnstile-response']` ada (input
tersembunyi dibuat), tetapi `iframe` Turnstile **0** dan `.cf-turnstile` **0** —
widget tidak terpasang. `document.activeElement` tetap `BODY`; klik tombol tidak
memicu apa pun.

Ini persis `AGENTS.md` pitfall #17: `110200` = **hostname belum terdaftar di
dashboard Cloudflare** (*Turnstile → widget → Settings → Hostname Management*).
Sitekey aktif: `0x4AAAAAAE7oKXWSyYpe2uj6` (dari `.env`, ter-bundle ke produksi).

Dampak pengguna: **fitur pelacakan via nomor pengajuan mati total**, dan UI
hanya menampilkan petunjuk "Selesaikan verifikasi captcha di atas untuk
mengaktifkan tombol Lacak" — padahal tidak ada captcha yang bisa diselesaikan.
Pengguna tidak punya jalan keluar; ini jalan buntu yang tampak seperti
kesalahan mereka.

Perbaikan **konfigurasi** (tetap diperlukan agar captcha hidup kembali):
daftarkan `medprom-metmal.vercel.app` **dan** `localhost`/`127.0.0.1` di
Hostname Management widget Turnstile.

Perbaikan **UX (sudah dikerjakan, 2026-09-30).** Sebelum konfigurasi itu
diperbaiki, halaman tidak boleh menjadi jalan buntu. Akar masalah kode yang
ditemukan saat mengukurnya: `Turnstile.tsx` mendaftarkan `error-callback` tetapi
**membuang sinyalnya** (`'error-callback': () => onTokenRef.current('')`),
sehingga kegagalan terjadi **senyap** — `ready` sudah `true` (placeholder
"Memuat verifikasi captcha…" hilang), tidak ada pesan galat, dan halaman terus
menyuruh pengguna menyelesaikan captcha yang tidak ada. Terukur: `iframe` 0,
`.cf-turnstile` 0, token `''`, `memuat: false`, `gagal: false`, tombol
`disabled: true`. Dikonfirmasi lewat probe langsung bahwa yang menyala adalah
`error-callback:110200` (bukan `timeout-callback`).

| Berkas | Perubahan |
|---|---|
| `src/components/ui/Turnstile.tsx` | `error-callback` kini menandai gagal (`setFailed(true)`), mengosongkan token, memanggil prop baru `onUnavailable(true)`, dan mengembalikan `true` (menandai galat sudah ditangani). Pesan galat diubah dari "Periksa koneksi" (menuduh koneksi pengguna, padahal bukan itu penyebabnya) menjadi jujur + langkah lanjut. Pemasangan ulang (`resetKey` naik) membersihkan keadaan gagal. |
| `src/components/promo/TrackSubmissionPage.tsx` | State `captchaUnavailable`; `captchaBlocked` kini `… && !captchaUnavailable`, sehingga tombol **tidak terkunci selamanya**; petunjuk "Selesaikan verifikasi captcha di atas" tidak lagi tampil saat widget memang tak ada; pesan "verifikasi sedang tidak tersedia, pencarian tetap dapat dicoba" ditampilkan sebagai `role="status"`. |

Verifikasi: 2 test baru di `Turnstile.test.tsx` (**terbukti merah** saat
perbaikan di-mutasi kembali - uji mutasi dijalankan). Jalur **sukses** juga
diuji ulang dengan sitekey uji resmi Cloudflare (`1x00000000000000000000AA`,
lewat env proses, `.env` tidak disentuh): token terbit (21 karakter), tidak ada
pesan gagal palsu → tidak ada regresi pada captcha yang bekerja.

**Catatan penting:** ini membuat kegagalan terlihat dan fitur tetap bisa
dipakai, **bukan** mengaktifkan captcha kembali. Tanpa langkah konfigurasi di
atas, `/lacak` berjalan tanpa captcha — dan server pun (fail-closed bila
`TURNSTILE_SECRET_KEY` terisi) akan menolak dengan `503`. Keduanya harus
diselaraskan.

## MEDIUM

### M1. Wizard cetak tidak memindahkan fokus ke field galat pertama

`PromoCetakWizard.tsx` **tidak punya** pemindah fokus: `grep -c fokusKeField`
= **0**, sedangkan `PromoUploadWizard.tsx` = **4**. Setelah submit gagal,
`document.activeElement` tetap `BODY`, sementara pesan galat muncul di tempat
lain di lembar yang panjang.

Terkait `DESIGN.md` ("PWA `display: standalone`"): di mode terpasang tidak ada
scroll bar yang memberi petunjuk posisi, jadi pengguna ponsel yang menekan
"Lanjut" dari dasar lembar tidak melihat apa pun berubah. `PromoUploadWizard`
sudah menyelesaikan ini lewat `fokusKeField()` (`focus({preventScroll:true})` +
`scrollIntoView({block:'center'})`).

Perbaikan: pakai ulang pola `fokusKeField` di wizard cetak (peta `FIELD_ID` +
`scrollIntoView`), dipanggil pada jalur submit gagal.

### M2. Pesan galat combobox tenant tidak diumumkan (`role="alert"` hilang)

`TenantSearchSelect.tsx:233` merender pesan galat **tanpa** `role="alert"`:

```tsx
{error && <p id={`${id}-error`} className="…">{error}</p>}
```

Bandingkan dengan setiap field lain di wizard yang sama — semuanya memakai
`role="alert"` (terukur: `err-pic_name`, `err-pic_phone` = `role="alert"`).
Akibat terukur saat submit kosong di `/ajukan-cetak`: yang diumumkan hanya
2 galat (`Nama pemohon wajib diisi.`, `Nomor telepon wajib diisi.`), sedangkan
galat field **pertama** — `Pilih tenant dari daftar, bukan ketik bebas.` —
**tidak diumumkan**.

`aria-describedby` sudah benar (terhubung ke `cetak-tenant-error`), jadi galat
tetap terbaca **saat field difokuskan**. Masalahnya: karena M1 juga membuat
fokus tidak berpindah, gabungan keduanya berarti galat pertama tidak pernah
sampai ke pengguna pembaca layar sampai ia menekan Tab ke belakang secara
manual.

Perbaikan: tambahkan `role="alert"` pada `<p>` galat itu (satu atribut).

## Audit lanjutan (pass 2) — kategori yang belum tersentuh

Pass pertama menandai kategori 3 (Performance) "tidak diukur". Pass kedua
menutupnya, plus menguji ulang kategori 2 (Touch) dengan ambang yang benar.

### Catatan cakupan: aturan mana yang berlaku

Proyek ini **web app** (React SPA + PWA `display: standalone`), bukan aplikasi
native. Karena itu yang berlaku adalah `references/quick-reference.md`
(stack-agnostic, web), **bukan** tabel di `references/pro-rules.md` yang secara
eksplisit menyatakan dirinya menyasar UI native/mobile (iOS/Android/RN/Flutter).
Konsekuensi praktisnya: ambang target sentuh yang mengikat adalah **WCAG 2.5.8
(24×24 px + pengecualian)**, bukan 44×44pt. Angka 44px tetap diukur di bawah
sebagai informasi, bukan sebagai kegagalan.

### P3-1. Code splitting — **diperbaiki**

Kategori 3 HIGH, aturan `bundle-splitting`. Terukur: `src/App.tsx` mengimpor
**kesepuluh** halaman secara statis, sehingga bundel awal memuat konsol staf
(`AdminDashboardPage`, 2.378 baris — modul terbesar di repo) dan kedua wizard
yang tidak pernah dibuka mayoritas pengunjung publik.

| | Sebelum | Sesudah |
|---|---|---|
| Bundel awal (JS) | 452,10 kB | **226,29 kB** |
| Bundel awal (gzip) | 119,90 kB | **73,13 kB** |
| `AdminDashboardPage` | ikut bundel awal | chunk terpisah 80,5 kB / 17,2 kB gzip |

`React.lazy` + satu `Suspense` di sekitar `<Routes>`, fallback `role="status"`
mengikuti pola pemuatan yang sudah dipakai repo. **Tanpa dependensi baru.**
Dua test rute disesuaikan `getByRole` → `findByRole` (kontrak rute tidak
berubah; hanya mekanisme muatnya). Service worker tidak perlu diubah: aset
ber-hash `/assets/*` sudah di-cache permanen dan `/` memakai network-first.

**Bukan pengamanan:** chunk konsol staf tetap dapat diunduh siapa pun yang
memintanya; otorisasi nyata ada di server. Yang dihemat hanya unduhan.

### P3-2. Atribut gambar — **diperbaiki**

Aturan `image-optimization` + `lazy-loading` + `image-dimension` (CLS).
Dari 3 `<img>` di repo, 2 sudah benar (landing katalog + pratinjau wizard punya
`width`/`height`/`loading="lazy"`/`decoding="async"`). Yang ketiga — foto
katalog di konsol staf — belum punya `loading`/`decoding`; ditambahkan
(CLS-nya sudah aman lewat `aspect-[4/3]`).

### P3-3. Service worker — **sudah benar, tidak diubah**

Diaudit karena SW yang salah adalah sumber bug "konten basi". Hasil: tidak
meng-cache permintaan API (`url.pathname.startsWith('/api/')` dilewatkan, dan
lintas-origin dilewatkan), navigasi SPA network-first dengan fallback shell,
aset ber-hash cache-first (aman karena nama ber-hash), `CACHE_VERSION`
di-naikkan per rilis, cache lama disapu di `activate`. Kebijakan "status
pengajuan wajib mutakhir" ditegakkan dengan benar.

### P3-4. Font — **sudah benar**

`display=swap` dipakai di URL Google Fonts, plus pola non-blocking
(`media="print"` + `onload`), `preconnect`, `preload`, dan fallback
`<noscript>`. Sesuai aturan `font-loading` + `font-preload`.

### P2. Target sentuh — diukur dengan ambang yang benar

Diukur ulang pada 375px di produksi, seluruh kontrol terlihat:

| Rute | Interaktif | < 44px | < 24px |
|---|---|---|---|
| `/` | 38 | 0 | 0 |
| `/lacak` | 7 | 0 | 0 |
| `/riwayat` | 6 | 0 | 0 |
| `/admin` (tabel) | — | 0 | 2 tautan (16px) |

Dua tautan 16px (`tautan materi`, `spanduk-andi.jpg`) di tabel konsol staf
**lolos pengecualian jarak WCAG 2.5.8**: diukur jarak tepi terdekat ke target
lain = **69px**, jauh di atas radius 12px yang disyaratkan. Jadi **bukan
pelanggaran** — dan keduanya tautan isi, bukan kontrol aksi utama.

Catatan: `/login` yang diukur di pass pertama ternyata **mengalihkan ke
`/admin`** karena sesi masih aktif (`AdminLoginPage.tsx:23`); angka 2 tautan
16px itu milik halaman admin, bukan halaman login. Dikoreksi di sini.

- **0 pelanggaran axe** di seluruh matriks (10 rute @1280 + 6 rute × 4 viewport
  lokal + 6 rute × 4 viewport produksi + `/admin` & `/status/:token` 3 viewport),
  filter `wcag2a/2aa/21a/21aa/22aa/best-practice`.
- **0 scroll horizontal**, 0 elemen meluber di luar container gulir yang
  disengaja, di 320/375/768/1440.
- **`h1` = 1 dan `main` = 1** di setiap rute.
- **Kontras AA lulus** (lihat Informasi). Token `DESIGN.md` akurat.
- **0 hex mentah di komponen** (`src/**/*.tsx` = 0; 137 kemunculan semuanya di
  `styles/`). Skala Tailwind dipetakan ulang di `@theme` sehingga komponen lama
  ikut dunia baru tanpa disentuh.
- **0 teks < 12px** (`text-[9px]`/`10px`/`11px` = 0), lantai `--text-meta` 12px
  ditegakkan.
- **0 emoji sebagai ikon**; ikon dari `lucide-react` dengan `aria-hidden`.
- **0 `transition-all`**, **0 `hover:scale`**, **0 animasi properti layout**
  (`width`/`height`/`top`/`left`). Durasi 120–150ms (rentang 150–300ms).
- **`prefers-reduced-motion` ditegakkan nyata**: diukur
  `transitionDuration`/`animationDuration` = `1e-06s`, dan `animate-spin`/
  `animate-pulse` dimatikan — dengan komentar yang menjelaskan mengapa durasi
  dipangkas, bukan `none` (agar `transitionend` tetap terpicu).
- **Cincin fokus terlihat**: Tab sungguhan → `outline: 2px solid rgb(20,64,214)`
  + ring, instan (transisi dimatikan saat `:focus-visible`, Gate 15).
- **0 tombol ikon tanpa nama aksesibel** (pemeriksaan AST-ish: 0 kandidat).
- **13/13 gambar punya `alt` non-kosong.**
- **`Sheet` adalah dialog yang benar**: `role="dialog"`, `aria-modal="true"`,
  `aria-label` = judul, **trap fokus bekerja** (8× Tab tetap di dalam;
  Shift+Tab melingkar dari elemen pertama ke terakhir), **Escape menutup**,
  scroll latar terkunci, fokus dipulihkan ke pemicu.
- **Wizard unggah langkah 2 — umpan balik galat teladan**: 8 `aria-invalid`,
  8 `aria-describedby`, 7 `role="alert"`, dan fokus berpindah ke field tidak
  valid pertama.
- **`/lacak`**: label + `htmlFor` benar, `autoComplete="off"`, petunjuk captcha
  eksplisit, tombol `disabled` sampai captcha selesai.
- **Tombol disabled punya tiga kanal**: `opacity` + `cursor: not-allowed`
  (aturan global `base.css`) + atribut `disabled`.
- **Target sentuh**: 0 kontrol < 24×24px di `/` (38 interaktif) dan di
  `/status/:token`. Satu-satunya yang lebih kecil adalah tautan dalam kalimat
  (`Lacak dengan nomor pengajuan`, 176×14) — dikecualikan WCAG 2.5.8 sebagai
  *inline text link*, sama seperti keputusan audit 2026-09-18.
- **Navigasi**: tabel rute bersih, rute tak dikenal → `Navigate to="/"`,
  deep link token status dimuat langsung (tanpa bergantung tombol back —
  penting untuk PWA standalone).
- **Gate**: `npm run build` hijau (12,61s, `tsc` bersih); `npx vitest run
  --maxWorkers=2` → 82 berkas / 653 test hijau.

## Risiko & rollback

Audit tidak mengubah apa pun → tidak ada yang perlu di-rollback. Untuk
perbaikan yang disarankan:

- **C1**: mengubah `VITE_PROMO_SHOW_DEV_LOGIN` hanya memengaruhi perenderan
  panel; rollback = kembalikan env + redeploy. **Reset password tidak bisa
  di-rollback** — lakukan setelah flag mati dan panel terverifikasi hilang.
- **H1**: murni konfigurasi dashboard Cloudflare; rollback = hapus hostname dari
  allowlist. Tidak menyentuh kode.
- **M1/M2**: perubahan lokal pada dua berkas wizard; rollback = `git revert`.
  M2 (satu atribut) tanpa risiko; M1 menuntut penyalinan pola `fokusKeField`
  yang sudah terbukti di wizard unggah.
