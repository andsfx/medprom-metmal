# PLAN 2026-09-25 09:15 (WIB) - Bukti pembayaran pajak media cetak

## Permintaan pemilik

> "tambahkan upload file pembayaran pajak di media cetak, bisa di on off oleh
> admin di dashboard"

Klarifikasi yang dipilih pemilik: pengunggah **keduanya** (tenant di wizard,
staf di dashboard), cakupan saklar **global seluruh media cetak**, dan sifat
**opsional** (tidak menghalangi pengiriman).

## Keputusan desain

1. **Saklar disimpan di server (tabel `app_settings`), bukan flag build-time.**
   Flag `VITE_*` di-inline saat build, sehingga "on/off oleh admin" tidak
   mungkin tanpa deploy ulang. `app_settings` sengaja generik (key-value) agar
   saklar berikutnya tidak menambah tabel.
2. **Bukti pajak melekat pada PENGAJUAN, bukan versi materi.** Ia dibayar
   sekali per pengajuan; memasukkannya ke `promo_submission_files` (yang
   menyimpan versi materi) akan memberi makna palsu pada riwayat versi.
3. **Gerbang di server, bukan hanya UI.** Saat saklar mati, field pajak dari
   klien diabaikan sepenuhnya. Menyembunyikan field saja akan menyisakan API
   yang bisa dipakai menulis data fitur yang mati.
4. **Fail-safe pada pembacaan saklar.** `isTaxProofEnabled()` menelan error DB
   (mis. tabel belum ada) dan mengembalikan `false`. Tanpa ini,
   `POST /promo/submit-batch` membalas 500 dan mematikan SELURUH pengajuan
   cetak pada jendela antara deploy kode dan migrasi.
5. **Satu berkas untuk seluruh batch.** Kiriman cetak berisi beberapa media;
   bukti pajak adalah pembayaran satu tagihan, jadi satu field di tingkat batch
   lalu didistribusikan ke tiap baris.

## Perubahan

### Skema (`server/schema.sql`, aditif di akhir berkas)
- `CREATE TABLE IF NOT EXISTS app_settings (key PK, value, updated_at)`.
- `INSERT ... ('tax_proof_enabled','false') ON CONFLICT DO NOTHING` - idempotent,
  tidak menimpa nilai yang sudah diubah admin.
- 7 kolom `tax_proof_*` pada `promo_submissions` (`ADD COLUMN IF NOT EXISTS`).
- Ditaruh SETELAH blok migrasi status (tanpa `DO $$`) sehingga uji urutan
  migrasi `__tests__/api/schema-migration.test.js` tidak terpengaruh.

### Server
- `server/src/lib/settings.js` (baru): `getSetting`, `setSetting`,
  `isTaxProofEnabled` (fail-safe).
- `server/src/routes/promo.js`: `GET /settings`; submit-batch membaca field
  pajak di `normalized`, menggerbangi dengan saklar, menambah 5 kolom ke
  `kolom`/`row` INSERT; `SUBMISSION_PUBLIC_COLUMNS` menambah 4 kolom pajak.
- `server/src/routes/admin.js`: `GET/POST /settings`;
  `POST /submissions/:id/tax-proof` (409 saat fitur mati, 404 tidak ada, 400
  bila tanpa PPN atau format salah, 503 tanpa Drive).

### Frontend
- `src/types/promo.ts`, `src/utils/promoApi.ts`, `src/utils/adminApi.ts`:
  tipe + klien untuk saklar, payload pajak, unggah staf.
- `PromoCetakWizard.tsx`: field unggah opsional di langkah 3 (hanya bila
  saklar menyala), unggah lewat `uploadFile` yang sudah ada.
- `AdminDashboardPage.tsx`: tab "Pengaturan" (saklar) + tampil/unggah bukti di
  sheet detail.
- `SubmissionDetail.tsx`: menampilkan bukti pajak ke tenant.

## Rilis

- **Wajib `npm run db:migrate`** di VPS (membuat tabel + kolom).
- Berkat fail-safe, urutan deploy aman: kode tanpa skema = fitur mati (bukan
  500). Tetap dianjurkan migrate lebih dulu.
- Tidak perlu `db:seed` (baris default dibuat oleh migrasi).
- Saklar tetap `false` setelah migrate; admin menyalakannya dari dashboard.
- `VITE_PROMO_SHOW_DEV_LOGIN` dibiarkan unset (blok akun demo tetap tampil
  sesuai permintaan pemilik).
