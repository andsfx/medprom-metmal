## Temuan & bukti

### 1. KRITIS — `Sheet` merebut fokus setiap render

`src/components/ui/Sheet.tsx:35` (`useEffect(..., [open, onClose])`).

Semua pemanggil mengirim `onClose` inline (`onClose={() => setDetail(null)}`,
`onClose={() => setForm(null)}`, `ConfirmDialog`), jadi identitasnya berubah
**setiap render**. Karena `onClose` menjadi dependency, efek "buka" berjalan
ulang tiap render: cleanup mengembalikan fokus ke pemicu, lalu
`panelRef.current?.focus()` merebutnya kembali ke panel dialog.

Bukti terukur (build produksi, `/admin`, klik nyata):

```
# modal Detail, textarea Catatan Review
ketik "Materi sesuai"  → nilai: "M"      ← hanya 1 karakter masuk
activeElement          → DIV (panel), bukan textarea

# modal Katalog, input Nama (mode Edit)
ketik "Spanduk Uji"    → nilai: "S"      ← hanya 1 karakter masuk
activeElement          → DIV (panel)
```

Dampak: **tiga dialog konsol staf** (Detail/review, form katalog, form
pengguna) + `ConfirmDialog` praktis tidak bisa diisi dengan keyboard. Catatan:
`fireEvent.change` di unit test tidak memicu render ulang React, sehingga
bug ini **tak terdeteksi** oleh suite yang ada — hanya muncul di peramban.

Perbaikan: simpan `onClose` di ref (`onCloseRef`) dan jadikan efek hanya
bergantung pada `open`. Setelah perbaikan (peramban): nilai utuh
(`"Materi sesuai ketentuan"`, `"Spanduk Uji"`), fokus tetap di input.

### 2. MAJOR — Wizard tidak mengarahkan fokus ke error pertama

`src/components/promo/PromoUploadWizard.tsx` (`goStep3`).

Bukti terukur (390×844, setelah menggulir ke bawah lalu menekan
"Lanjut — Kirim Materi"):

```
scrollTop sebelum        : 473
fokus setelah validasi   : tombol (tidak berpindah)
field invalid pertama    : #tenant-search, top = -232px  ← DI ATAS layar
terlihat                 : false
```

Enam pesan `role="alert"` dirender, tetapi pengguna yang sudah menggulir tidak
melihat satu pun. Melanggar WCAG 3.3.1 (error identification).

Perbaikan: efek baru memindahkan fokus + `scrollIntoView({block:'center'})` ke
field tidak valid pertama menurut **urutan DOM** (bukan urutan pemeriksaan),
dipicu `focusErrorTick` (bukan `fieldErrors`, agar memperbaiki satu field tidak
merampas fokus). Diterapkan pada jalur validasi klien (`goStep2`/`goStep3`),
`linkError`/`termsAccepted`, dan validasi server yang dipetakan ke field.
Setelah perbaikan: `activeElement = tenant-search`, `top = 283px`,
`terlihat = true`, `scrollTop = 0`.

### 3. MAJOR — `/riwayat` menelan galat API

`src/utils/promoApi.ts:187` — `fetchMySubmissions` mengubah **setiap**
`ApiError` menjadi `[]`.

Bukti terukur (respons `/promo/submissions/mine` disuntik `503`):

```
teks layar : "Belum ada pengajuan dari perangkat ini."
[role=alert] : 0
```

Tenant diberi tahu pengajuannya **tidak ada** padahal server hanya sedang
bermasalah — informasi menyesatkan. Perbaikan: galat diteruskan; halaman
menambahkan state `loadError` dengan panel galat + jalan keluar ke `/lacak`.
Setelah perbaikan: panel "Gagal memuat riwayat pengajuan" muncul (`role=alert`,
1 node), dan state kosong asli tetap terpisah.

### 4. MAJOR — Tautan salah label di keadaan kosong `/riwayat`

`src/components/promo/MySubmissionsPage.tsx:70` — CTA berlabel **"Ajukan
Materi"** mengarah ke `/` (katalog), bukan `/ajukan`.

Bukti: `page.$$eval('a')` → `{ text: "Ajukan Materi", href: "/" }`.
Label menjanjikan formulir pengajuan tetapi mendaratkan pengguna di katalog —
satu langkah tambahan yang tidak diminta. Perbaikan: tujuan diubah ke
`/ajukan` (label sudah benar, tujuan yang salah). Teks pendamping "dari halaman
beranda" juga diperbaiki karena tidak lagi akurat.

### 5. MAJOR — Tab admin tidak bisa dipindah dengan keyboard

`src/components/admin/AdminDashboardPage.tsx:1529` — `role="tablist"` tanpa
`onKeyDown`, tanpa `aria-controls`/`role="tabpanel"`, tanpa roving `tabIndex`.

Bukti terukur (fokus di tab pertama, tekan `ArrowRight` 2×):

```
aktif    : "Pengajuan" (tidak berpindah)
selected : ["true","false","false"] (tidak berubah)
```

`role="tablist"` menjanjikan pola keyboard ARIA; tanpanya pengguna keyboard
tidak punya cara berpindah tab selain Tab+Enter (yang tetap bekerja). Tabel
admin juga scroll horizontal (`scrollWidth 760` vs `clientWidth 343`) — sesuai
kontrak DESIGN.md, tidak mengecilkan teks.

Perbaikan: roving `tabIndex`, `onKeyDown` (←/→/↑/↓/Home/End, dengan wrap),
`aria-controls` + `role="tabpanel"`. Setelah perbaikan: panah memindahkan
fokus & pilihan (`Pengajuan → Katalog Media → Pengguna → Pengajuan`), `Home`
dan `End` bekerja, `aria-selected` mengikuti.

### 6. MAJOR — `/lacak`: hasil muncul di bawah lipatan tanpa umpan balik

`src/components/promo/TrackSubmissionPage.tsx` (render `data`).

Bukti terukur (390×844, pencarian berhasil):

```
scrollTop : 0
fokus     : track-number
liveRegion: (tidak ada)
```

Detail dirender di bawah formulir, di luar layar, tanpa pemindahan fokus
maupun live region — pengguna hanya melihat formulir yang sama. Perbaikan:
kontainer hasil diberi `tabIndex={-1}` + `aria-label="Hasil pelacakan"` dan
difokuskan/digulirkan saat **pengajuan berganti** (muat ulang pasca-revisi
tidak merampas fokus dari form revisi). Setelah perbaikan:
`activeElement = "Hasil pelacakan"`.

### 7. MAJOR — Kontrol di bawah 44px

Kontrak DESIGN.md: "Setiap kontrol interaktif minimal 44×44 px". Bukti
terukur di build produksi (390×844), **sebelum** perbaikan:

| Lokasi | Kontrol | Tinggi |
|---|---|---|
| `/admin` tab | "Pengguna" (non-aktif) | 36 |
| `/admin` tabel | Hapus pengajuan / Hapus media / Hapus user | 28 |
| `/admin` tab Katalog | "Tambah Media" | 40 |
| `/admin` tab Pengguna | "Tambah User" | 40 |
| `/admin` sheet | Batal / Simpan / Simpan Status | 42 |
| `/ajukan` langkah 3 | Kirim Tautan / Unggah File | 42 |
| `/ajukan` langkah 3 | Hapus file | 28 |
| `/riwayat` kosong | CTA "Ajukan Materi" | 36 |
| `/status/:token` | CTA "Lacak dengan Nomor Pengajuan" | 36 |
| `/status/:token` revisi | Kirim Tautan / Unggah File | 38 |

Setelah perbaikan (`min-h-11` pada tombol/CTA, `h-11 w-11` pada tombol ikon):
tinggal **tautan inline** yang < 44px — `/` "Lacak dengan nomor pengajuan"
(38px, di tengah kalimat), `/lacak` "Riwayat" (16px), `/admin` nama berkas
(16px). WCAG 2.5.8 mengecualikan *inline text link*; ini **bukan pelanggaran**
(sejalan dengan keputusan audit 2026-09-18). Radio/checkbox 16px berada di
dalam `<label>` yang menjadi target klik penuh — sesuai praktik standar.

### 8. MINOR — Atribut ARIA error tidak lengkap

`PromoUploadWizard.tsx` — `installation_date`, `air_end_date`,
`terms_accepted` tidak punya `aria-invalid`/`aria-describedby`; pesan error
`media` tanpa `role="alert"`/`id`. Perbaikan: ketiganya ditautkan; radio media
diberi `id="media-0"` + `aria-describedby` dan pesannya `role="alert"`.

### 9. MAJOR — Keadaan kosong hilang di dua tab konsol staf

`AdminDashboardPage.tsx` — `CatalogTab` (`{!loading && (<div className="grid …">`) dan
`UsersTab` (`{!loading && (<div className="overflow-x-auto">`) merender wadahnya
**tanpa pesan apa pun** bila `rows.length === 0`. Terukur (API disuntik daftar
kosong): grid/tabel kosong, tanpa satu pun teks keadaan kosong.

Dampak: staf melihat layar kosong dan tidak tahu apakah katalog benar-benar
kosong atau masih memuat. Perbaikan: panel `ui-empty-panel` (pola yang sudah
dipakai `/riwayat`) + teks arahan sesuai peran (`canManage`), diumumkan lewat
`role="status"`.

### 10. MINOR — Keadaan kosong tabel Pengajuan tidak diumumkan

`AdminDashboardPage.tsx` — pesan "Tidak ada pengajuan." sudah ada tetapi tanpa
`role="status"`, sehingga pembaca layar tidak mengumumkannya. Ditambahkan.

### 11. MAJOR — Aturan "Catatan Review wajib" tidak ditegakkan di klien

Label UI berbunyi "Catatan Review (wajib untuk Perlu Revisi dan Ditolak)", dan
server menegakkannya (`server/src/routes/admin.js:232-237` → `400`), tetapi
klien tidak: terukur — memilih "Perlu Revisi" dengan catatan kosong membuat
tombol "Simpan Status" tetap aktif dan tanpa peringatan; admin baru tahu
**setelah** submit (round-trip gagal).

Perbaikan (cermin aturan server, server tetap otoritatif): `STATUS_WAJIB_CATATAN`
+ `PESAN_CATATAN_WAJIB`, tombol `disabled` bila status mewajibkan catatan dan
catatan kosong, pesan inline `role="alert"` bertaut `aria-describedby`. Pesan
galat server tidak dihapus. Terukur setelah perbaikan: tombol `disabled`, pesan
"Catatan wajib diisi saat meminta revisi materi.", `aria-invalid=true`,
`aria-describedby=err-review-notes`; mengisi catatan membuka kunci kembali.

### 12. MAJOR — Tautan "Buka" versi materi di bawah target 24px (pre-existing)

Temuan **sudah ada di HEAD** (dibuktikan: build HEAD → `target-size(2)`), bukan
regresi perubahan ini, dan berada di area workflow yang diaudit. axe: tautan
44.5×16px dengan ruang klik aman 20px (< 24px). Karena ini tautan kontrol
berdiri sendiri di baris daftar (bukan tautan inline di tengah kalimat),
pengecualian WCAG 2.5.8 tidak berlaku. Perbaikan: `min-h-11`. Terukur setelah
perbaikan: modal Detail **0 pelanggaran** axe.

## Sengaja dibiarkan — USULAN (mengubah perilaku produk)

### U1. Back `/status/:token` tidak kontekstual
`SubmissionStatusPage.tsx:37` memakai `backTo="/riwayat"` statis. Terukur:
masuk dari `/lacak` → tombol Kembali tetap ke `/riwayat`, bukan `/lacak`.
Usul: simpan asal navigasi (state router) atau ubah label menjadi "Ke Riwayat".
Perlu keputusan karena mengubah perilaku.

### U2. Jalan keluar `/lacak` dan `/login`
`/lacak` punya nav top-level lengkap (mobile & desktop) — aman. `/login`
hanya punya satu tautan teks "← Kembali ke halaman publik" (terukur: 1 tautan,
0 landmark `nav`). Secara DESIGN.md ("tidak boleh ada layar yang bergantung
tombol back peramban") ini **terpenuhi**, tetapi jalan keluarnya tidak berada
di posisi app bar seperti layar lain. Usul: pindahkan ke tombol back app bar
atau tambah nav; perlu keputusan desain.

### U3. Konsistensi judul & landmark di desktop
Judul app bar `/ajukan` = "Ajukan Materi" sementara label langkah = "Pilih
Media"/"Data Tenant"/"Kirim Materi". `/ajukan` juga satu-satunya rute dengan
`nav` (langkah pengajuan) **tanpa** `aria-label` "Navigasi utama" — konsisten
dengan `hideTabBar`, tetapi bila kelak tab bar muncul di rute ini akan ada dua
`nav`. Usul: pertimbangkan `aria-label` eksplisit; perlu keputusan.

## Yang diverifikasi TIDAK bermasalah (jangan diutak-atik)

- **Graf rute**: 7 rute + fallback `*` → `/`; setiap layar punya jalan keluar
  yang **tidak** bergantung tombol back peramban (`/` katalog+tab,
  `/ajukan` back+sukses, `/riwayat` tab, `/lacak` tab, `/status/:token` back +
  dua CTA, `/login` tautan kembali, `/admin` Beranda+Logout+tab).
- **Semantik back wizard**: terukur — langkah 2 → Kembali → tetap `/ajukan`
  (langkah 1); langkah 1 → Kembali → `/`. Bukan riwayat peramban.
- **Indikator progres wizard**: tampil mobile & desktop (lebar 640px, tinggi
  4px, teks "Langkah N dari 3", `role="progressbar"` dengan nilai).
- **Dokumen tidak menggulir**: `documentElement.scrollHeight === innerHeight`
  di `/`, `/riwayat`, `/lacak`, `/status` (844 = 844); hanya `.app-scroll`
  yang menggulir; app bar `position: sticky` tidak bergeser.
- **Konsol staf mobile**: 3 tab berfungsi (klik), tabel scroll horizontal,
  header 89px (bukan 130px).
- **Semua dialog memakai `Sheet`**: `grep` memastikan `app-scrim`/`app-sheet`
  hanya ada di `Sheet.tsx` (0 salinan di JSX lain).
- **Pemulihan fokus Sheet**: terukur — tutup dialog → fokus kembali ke tombol
  "Detail" pemicu.
- **Checklist DESIGN.md lain**: 0 `Bricolage`, 0 `rounded-2xl/3xl`, 0
  `brand-secondary`/`brand-pink`, 0 `--brand-paper`, 0 `ui-dashboard-*`, 0
  `transition-all`.
- **axe-core**: 0 pelanggaran di 7 rute (sebelum & sesudah).
