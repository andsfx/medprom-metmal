# Audit UI/UX — medprom-metmal

**Tanggal:** 2026-09-16 19:05 WIB
**Cakupan:** seluruh antarmuka (sisi tenant + konsol staf), kerangka aplikasi,
target sentuh, aksesibilitas dialog, keseragaman token
**Acuan:** `DESIGN.md`, WCAG 2.2 AA
**Status:** selesai — 7 temuan nyata diperbaiki, terverifikasi di peramban

## Tujuan

Memastikan antarmuka benar-benar sesuai `DESIGN.md` dan layak disebut
"aplikasi" — bukan sekadar tampak seperti aplikasi. Audit dilakukan dengan
**pengukuran di peramban sungguhan** terhadap build produksi, bukan telaah kode
saja, karena beberapa kelas masalah (gulir, fokus, kontras efektif) tidak
terlihat dari sumber.

## Metode

1. Inventaris komponen/halaman + pembacaan `theme.css`/`base.css` sebagai
   sumber kebenaran token.
2. Pengukuran terprogram di Chromium: `getComputedStyle`, `getBoundingClientRect`,
   `document.scrollingElement.scrollHeight`, penghitungan kontras WCAG.
3. Uji perilaku: gulir dokumen vs area konten, `Escape`, jebakan fokus, kunci
   gulir, target sentuh, radius efektif.
4. Uji kontrol (halaman polos) untuk memisahkan bug aplikasi dari artefak
   emulasi peramban.

## Temuan

### T1 — Kerangka tidak mengunci gulir (berat)

**Gejala.** `document.scrollingElement.scrollHeight` = 4839px pada viewport
844px; `window.scrollTo(0, 900)` berhasil; app bar bergeser −900px saat
dokumen digulir. Klaim inti "hanya area konten yang menggulir" tidak terpenuhi,
dan `data-elevated` tidak pernah menyala di landing.

**Akar masalah.** Bukan `min-height` (itu memang perlu, tapi bukan penyebabnya).
Ternyata `.app-scroll` tidak terposisi, sehingga `<dt class="sr-only">` di dalam
kartu media — yang `position: absolute` — mengambil containing block dari
**dokumen**, bukan dari area gulir. Elemen 1×1 itu memanjangkan tinggi gulir
dokumen ke 4839px dan membatalkan penguncian.

**Bukti isolasi.**

| Uji | `html.scrollHeight` |
|---|---|
| baseline | 4839 |
| `.app-scroll` disembunyikan | 844 |
| `.app-scroll { overflow: hidden }` | 4839 (tidak menolong) |
| `.app-shell { position: relative }` | **844** |
| `.app-shell { contain: paint }` | **844** |

Kontrol dengan halaman polos membuktikan pola CSS-nya sendiri benar
(`html.scrollHeight` = 844, tidak bisa digulir) — jadi memang ada elemen
absolute yang bocor dari container.

**Perbaikan.** `.app-shell` → `height: 100dvh; overflow: hidden`.
`.app-scroll` → `min-height: 0` **dan** `position: relative`.

**Verifikasi.** `html.scrollHeight` = 844 = `innerHeight`; `scrollTo(0,900)`
tidak menggerakkan dokumen; `sc.scrollTop = 900` berhasil; app bar tetap di
`top: 0` selama konten digulir; `data-elevated="true"` kini menyala.

### T2 — Tiga dialog konsol staf kehilangan perilaku modal (berat)

Detail/review, form katalog, dan form pengguna adalah salinan
`.app-scrim` + `.app-sheet` langsung di JSX, bukan komponen `Sheet`.

| Perilaku | Sebelum | Sesudah |
|---|---|---|
| `body.overflow` saat terbuka | `""` (tidak dikunci) | `hidden` |
| `Escape` menutup | tidak | ya |
| Fokus dipindah ke dalam dialog | `BODY` | ya |
| `aria-label` | tidak ada | judul dialog |

Perbaikan: ketiganya memakai `<Sheet>`. Terverifikasi di mobile (menempel
bawah, radius atas 20px/bawah 0, ada pegangan) dan desktop (640px, terpusat,
radius seragam 14px).

### T3 — `ConfirmDialog` sama-sama tidak menutup dengan `Escape` (sedang)

Tidak mengunci gulir latar dan tidak menutup dengan `Escape`. Kini memakai
`Sheet`; terverifikasi fokus terjebak di dalam dialog dan `Escape` menutup.

### T4 — Form login terpotong di layar pendek (sedang)

`.app-shell` memusatkan konten tanpa area gulir. Pada viewport 360×420,
`scrollHeight` kanvas 618px > 420px tetapi tidak dapat digulir — tombol Login
tidak terjangkau.

Perbaikan: kelas baru `.app-canvas` (terpusat, `overflow-y: auto`,
`min-height: 0`). Terverifikasi: `scrollTop` maksimum 198px, tombol Login
terjangkau.

### T5 — Belasan kontrol di bawah 44px (sedang)

Diukur pada landing mobile: 30 kontrol di bawah ambang.

| Kontrol | Tinggi |
|---|---|
| CTA kartu katalog | 40px |
| Tombol "Ketentuan pemasangan" | 20px |
| Tautan "Login Staf" | 36px |
| Tautan WhatsApp | 30px |
| Tombol tampilkan-password (login) | 24px |
| Seluruh input | 42px |

Perbaikan: `--tap-min` ditegakkan pada `.ui-control` (satu aturan mencakup
seluruh input, select, dan tombol sekunder), tombol tampilkan-password
dinaikkan ke 44×44, dan tombol-tombol terkait diberi `min-h-11`.
**Terverifikasi: 0 kontrol di bawah 44px** di halaman publik.

Catatan: ambang AA WCAG 2.2 (2.5.8) adalah 24px, jadi ini bukan pelanggaran
AA — tetapi `DESIGN.md` sendiri menetapkan 44px, dan standar internal itu yang
ditegakkan.

### T6 — Radius tombol tidak seragam (ringan)

CTA kartu katalog dirender 6px sementara seluruh kontrol lain 10px, karena
radius bergantung pada kelas utilitas per pemakaian. `.ui-btn-primary` dan
`.ui-btn-secondary` kini mengambil `var(--radius-control)` dari token, jadi
tombol yang lupa membawa kelas radius tetap seragam. Terverifikasi: seluruh
tombol 10px, kartu 14px.

### T7 — Komentar & dokumen usang (ringan)

- `BottomTabBar.tsx` menyebut `sm:hidden`, padahal penyembunyian sudah
  dipindah ke `base.css` (dan komentar itu menyesatkan arah perbaikan).
- `DESIGN.md` masih menyatakan "tidak ada dark mode di v1", padahal varian
  `.dark` sudah ada; masih menulis wizard memakai angka besar `01/02/03` dan
  "tidak ada progress bar"; masih menulis radius lewat kelas utilitas.

Semuanya diselaraskan dengan kode.

## Temuan dokumentasi (lanjutan)

Tiga klaim `DESIGN.md` ternyata **bertentangan dengan kode**, bukan sekadar
kurang lengkap — semuanya sudah diselaraskan:

| Klaim lama | Kenyataan di kode |
|---|---|
| Hero `text-4xl sm:text-6xl`; ada "Number XL" `text-6xl sm:text-8xl` | Nol pemakaian `text-6xl`/`text-8xl`; H1 sebenarnya `text-2xl sm:text-4xl` |
| `01/02/03` adalah penanda langkah wizard | Wizard memakai indikator progres bersegmen; tidak ada angka besar |
| "maksimal dua sentuhan tosca per viewport" | Kartu katalog memakai **empat** ikon tosca (ukuran, material, harga, lokasi) |

Klaim terakhir paling penting karena berbentuk **aturan yang tidak dapat
ditegakkan**: aturan itu ditulis untuk tata letak editorial tanpa kartu data.
Alih-alih memaksa UI mengikuti angka yang salah, aturannya dipecah:

- **Aksen struktural** (CTA, tautan aktif, focus ring, angka statistik) —
  maksimal satu per viewport.
- **Aksen ikon berulang** (ikon baris metadata) — boleh mengikuti jumlah baris
  data; ukurannya kecil dan selalu mendampingi teks.

Batas yang tetap dipertahankan: tosca tidak pernah menjadi permukaan, tidak
pernah mewarnai teks paragraf, dan tidak pernah menghias section menyeluruh.

Bagian "Nomor & Langkah" diganti menjadi **"Angka & Statistik"** dengan catatan
eksplisit agar angka display raksasa tidak dihidupkan kembali.

## Audit lanjutan: kaidah platform app

Pemeriksaan kedua terhadap kaidah aplikasi mobile (Apple HIG, Material Design,
WCAG 2.2), diukur di peramban pada viewport 390×844.

### Cacat yang diperbaiki

**P1 — Wizard tidak menggulir ke atas saat pindah langkah.**
Diukur: pengguna menggulir langkah 1 sampai bawah (`scrollTop` 587), memilih
media, menekan Lanjut → `scrollTop` **tidak direset** dan judul langkah 2
berada **639px di atas layar**. Fokus tetap di `BODY`. Perbaikan: efek pada
perubahan `step` menggulir `.app-scroll` ke atas dan memfokuskan judul langkah
(`tabIndex={-1}`). Terverifikasi: `scrollTop` 587 → **0**, judul terlihat pada
153px, fokus `H2:Data Tenant & PIC`.

**P2 — Dua `<h1>` bersamaan di wizard; nol `<h1>` di `/admin`.**
Judul app bar dan judul langkah sama-sama `<h1>`. Diseragamkan: app bar `<h1>`
(nama layar), judul konten `<h2>`. `/admin` yang tanpa heading kini memakai
`<h1>`. Terverifikasi: katalog/wizard/riwayat/status masing-masing tepat satu
`<h1>`.

**P3 — Pesan error tidak dikaitkan ke field.**
`aria-describedby` nol pemakaian di seluruh wizard: pembaca layar tahu field
tidak valid (`aria-invalid`) tetapi tidak pernah membacakan pesannya. Delapan
field kini menautkan ke `<p id="err-*" role="alert">`.

**P4 — Safari iOS zoom otomatis pada input.**
Semua 12 input teks berukuran 14px; Safari iOS memperbesar halaman bila
`font-size` < 16px, dan tidak mengembalikannya. Kontrol isian dinaikkan ke
16px pada `< 640px` — hanya untuk `input/select/textarea`, bukan tombol, agar
kepadatan tetap. Tidak memakai `maximum-scale=1` karena memblokir pinch-zoom
(WCAG 1.4.4).

### Yang diperiksa dan dinyatakan SUDAH sesuai (tidak diubah)

Penting dicatat agar tidak "diperbaiki" tanpa alasan di kemudian hari:

- **Checkbox & radio: 13 dari 13 sudah di dalam `<label>`** berukuran
  70×316px. Target sentuh efektifnya adalah baris label, bukan kotak 16px —
  jadi lolos ambang meski kotaknya kecil.
- **`inputMode` & `type` sudah tepat**: `type="tel"` + `inputMode="tel"` untuk
  telepon, `type="url"` + `inputMode="url"` untuk tautan, `type="date"` untuk
  tanggal, `autoComplete` pada nama/telepon/email.
- **`prefers-reduced-motion`** mematikan animasi tekan (`.app-pressable`).
- **Tidak ada gambar tanpa `alt`**, tidak ada tombol/tautan tanpa nama aksesibel.
- **Pinch-zoom tidak diblokir** — viewport meta tidak memuat
  `maximum-scale`/`user-scalable=no`.
- **Pemuatan & galat diumumkan**: `role="status"` untuk pemuatan,
  `role="alert"` untuk galat.

### Pelajaran proses

Saat mengganti tag HTML secara massal dengan skrip, **tag penutup ikut
diganti**. Penggantian `<h1 …>` → `<h2 …>` di `SubmissionStatusPage.tsx`
sempat menyisakan `</h1>` dan merusak JSX; tertangkap `tsc` sebelum dikirim.
Karena itu `tsc` wajib dijalankan setelah setiap penyuntingan skrip, bukan
hanya sebelum commit.

## Audit ketiga: layout, heading, penempatan teks

Dipicu umpan balik pengguna: "perbaiki layout dan heading serta penempatan

### Acuan yang dipakai

Pengguna memasang 8 skill UI/UX khusus. Dipakai yang relevan:

- `ui-ux-pro-max` — tool pencarian lokal (`scripts/search.py`). Kutipan yang
  mengoreksi pekerjaan ini:

## Audit skill ui-ux-pro-max (2026-09-17): token warna + reduced-motion

Skill `ui-ux-pro-max` dipanggil dengan target project ini. Stack terdeteksi
React 19 + Tailwind 4; design system generik ditarik, lalu DIBANDINGKAN dengan
DESIGN.md (otoritas incumbent) alih-alih diterapkan mentah-mentah.

**Rekomendasi generik skill yang DITOLAK:**
- Warna Primer #1E40AF/Onyx dsb. — generik "Enterprise Gateway", tidak cocok;
  identitas incumbent (tosca Metmal #00918e, Fraunces + Geist) dipertahankan.
- CTA biru, mega-menu, logo carousel — tidak relevan untuk portal operasional.

**Q1 - 38 heksadesimal arbitrer di komponen.** Melanggar aturan skill
(`color-semantic`, prioritas 6) SEKALIGUS aturan AGENTS.md ("warna via token").
Setiap nilai punya pasangan token sama persis. Sesudah: tidak ada lagi `[...]`
hex di `src/components/`. Verifikasi: baseline 961 elemen di 5 layar
(katalog/wizard/riwayat/login + login gelap), hasil terhitung IDENTIK.

**Q2 - reduced-motion tak digerbangi.** Terukur dengan emulasi media:
`animate-spin` = `spin/1s/infinite` dan `animate-pulse` = `pulse/2s/infinite`
BAHKAN saat `prefers-reduced-motion: reduce`. Berbeda dengan skeleton di
`index.html` yang sudah digerbangi `no-preference` — konvensi ada, komponen
tidak ikut. Sesudah: `animation: none` di blok reduced-motion base.css;
terukur `none/0s/1`, normal tetap `spin/1s/infinite`. Aman karena tiap spinner
punya teks pendamping; tidak ada `aria-busy` di repo, tapi status disampaikan
lewat teks berubah ("Mengirim…", "Memuat riwayat…").

### Yang diperiksa dan dinyatakan sesuai


- **Kontras.** Semua kombinasi lolos: badge tosca 6.52:1, eyebrow 5.18:1,
  muted 4.76:1, sekunder 10.35:1, amber 6.37:1. Tosca-500 di atas putih
  (3.86:1) hanya dipakai untuk ikon/aksen, bukan teks — sesuai kebijakan.
- **Tidak ada sisa pola event.** Nol kemunculan `rounded-2xl`/`rounded-3xl`,
  `Bricolage`, `brand-secondary`, `brand-pink`, `--brand-paper`, `shadow-card`,
  `ui-dashboard-*`.
- **Struktur tab admin.** `role="tablist"` dengan `role="tab"` +
  `aria-selected` — benar.
- **Tabel admin.** `overflow-x-auto` dengan `min-w-[640px]`; teks tidak
  dikecilkan.
- **Tab bar mobile-only.** `grid` di mobile, `none` di ≥640px.
- **Fokus.** `.ui-focus-ring` menghasilkan ring 2px tosca dengan offset;
  `.ui-btn-primary:focus-visible` memakai outline 2px.
- **Judul per layar.** Tidak ada duplikasi `h1` setelah perbaikan sebelumnya.

## Risiko & rollback

Perubahan menyentuh CSS kerangka dan struktur JSX dashboard. Rollback:
`git revert` commit audit ini lalu deploy ulang. Karena aset shell berubah,
`CACHE_VERSION` di `public/sw.js` dinaikkan ke `v2` — klien lama akan menyapu
cache `v1` pada event `activate`. Bila perlu rollback cepat pada klien yang
sudah terpasang, naikkan kembali `CACHE_VERSION`.
