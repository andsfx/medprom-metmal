# PLAN 2026-09-25 13:58 - UI/UX mobile (audit + perbaikan)

## Tujuan

Memastikan seluruh permukaan layak pakai di ponsel ("pastikan bagus di
mobile"), dengan bukti terukur - bukan penilaian visual saja.

## Cara audit

- Playwright 1.63 (Node) + `scripts/preview-server.mjs` yang menyajikan
  `dist/` dan mem-proksikan `/api/*` ke API produksi, sehingga katalog nyata
  ikut ter-audit tanpa melonggarkan CORS produksi.
- Dua viewport gate: **360x740** dan **320x568** (320 = batas bawah realistis).
- Tujuh rute: `/`, `/ajukan`, `/ajukan-cetak` (langkah 1-3), `/lacak`,
  `/status/:token`, `/riwayat`, `/admin` (login staf).
- Metrik objektif: gulir horizontal tingkat halaman, teks < 12px, target
  sentuh < 44px, luapan elemen, jumlah baris nilai `.doc-row`.

## Temuan

### 1. Teks di bawah 12px (86 tempat)

`text-[11px]` 84x + `text-[10px]` 2x di `AdminDashboardPage.tsx` (53),
`PromoUploadWizard.tsx` (17), `PromoCetakWizard.tsx` (14),
`PromoLandingPage.tsx` (2). DESIGN.md menetapkan "Tidak ada teks di bawah
12px" dan `--text-meta` = 12px sebagai batas bawah. Semuanya label kapital
ber-track - justru teks yang paling sulit dibaca di ponsel.

Bukti bahwa ini nyata, bukan artefak emulasi: elemen lencana ukuran di landing
("0.9 M x 6.0 M") terukur 11px pada `isMobile: true` DAN `isMobile: false`.
`--text-meta` sendiri 12px; nilai 11px berasal dari utilitas arbitrer.

### 2. Tabel titik penghubung rusak di layar sempit

`.doc-row` = flex `dt` (label, nowrap) + `.doc-leader` (flex:1, min-width
0.75rem, garis titik) + `dd` (mono 14px, rata kanan, tanpa `min-width:0`).
Nilai panjang membungkus 2-3 baris sementara titik penghubung menyusut ke
minimum 12px, sehingga terbaca:

```
Material ..... Sticker di Impraboard      (nilai 2 baris, titik jadi stub)
Periode .... 2026-09-28 s/d 2026-10-05 (10 hari lagi)
```

Terukur: 17 dari 44 baris katalog membungkus di 320px, 9 dari 44 di 390px.
Membungkus juga terjadi di 1280px (9/44) tetapi di sana titik penghubung
panjang sehingga masih terbaca wajar - karena itu perbaikan dibatasi ke mobile.

### 3. Nominal rupiah terbelah dari "Rp."

Di 320px baris biaya ringkasan terbelah `Rp.` / `543.900`, nominal jadi yatim.

### 4. Nomor pengajuan staf membungkus tiga baris

`MP-260919-EKWNQU` terbelah `MP-` / `260919-` / `EKWNQU` di kolom sempit.

### Bukan cacat (diverifikasi)

- **Tabel staf `min-w-[640-760px]`**: sudah di dalam `overflow-x-auto`, jadi
  gulir terjadi di dalam wadah, bukan di halaman. Ini tradeoff kepadatan yang
  disengaja DESIGN.md ("Kepadatan dan kecepatan pindai di atas kesan visual").
  Diukur: `docW == viewport` di 360px dan 320px.
- **Semua input 45px** (>= 44px `--tap-min`). Heuristik audit pertama salah
  karena mengambil kotak caption label, bukan kotak input.
- **Safe area**: `.app-scroll`, `.app-bar`, `.app-tabbar`, sheet, dan
  `.app-scroll[data-tabbar='off']` sudah memakai `env(safe-area-inset-*)`;
  perilaku `data-tabbar` terkunci `AppShell.test.tsx`.
- **Tautan inline** ("Lacak dengan nomor pengajuan") < 44px: dikecualikan WCAG
  2.5.8 (Inline).

## Perbaikan

| # | Berkas | Perubahan |
|---|---|---|
| 1 | 4 komponen | `text-[11px]`/`text-[10px]` -> `text-xs` (12px), 86 tempat |
| 2 | `src/styles/base.css` | `@media (max-width: 639px)`: `.doc-row` ditumpuk, `.doc-leader` disembunyikan, `dd` rata kiri + `overflow-wrap: break-word` |
| 3 | `PromoCetakWizard.tsx` | `rupiah()` memakai U+00A0 setelah "Rp." |
| 4 | `AdminDashboardPage.tsx` | `whitespace-nowrap` sel nomor + tanggal; `break-all` sel email |

Catatan desain: perbaikan #2 harus tinggal di `base.css` sebagai kelas tak
berlapis, bukan utility Tailwind - Tailwind v4 menaruh utility di `@layer`,
sehingga kelas tak berlapis selalu menang (alasan yang sama sudah dipakai
`.ui-admin-title`). Spesifisitas ditulis `.doc-rows > .doc-row > dd` agar
seri dengan aturan dasar dan menang sebagai aturan berikutnya.

## Yang DITOLAK (dengan bukti)

Usulan memecah baris biaya menjadi `<span class="whitespace-nowrap">` per
nominal **dibatalkan setelah diuji**: `@testing-library/dom` `getNodeText()`
hanya membaca text node LANGSUNG, sehingga memecah string utuh menjadi span
membuat `PromoCetakWizardTotal.test.tsx:164`
(`getByText('Rp. 490.000 + PPN Rp. 53.900 = Rp. 543.900')`) dan `:217` gagal,
dan `getByText('Rp. 53.900')` menjadi ambigu (2 elemen). Dibuktikan dengan
menjalankan tes: **5 tes merah**. Patch dikembalikan.

Solusi yang dipakai (U+00A0) menyelesaikan masalah yang sama TANPA menyentuh
kontrak: normalizer testing-library memperlakukan U+00A0 sebagai whitespace
(`\s` di JS mencakup `\u00A0`), jadi `getByText('Rp. 543.900')` tetap cocok
sementara browser tidak lagi memutus baris di antara "Rp." dan nominalnya.
