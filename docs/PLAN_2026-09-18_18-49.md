# Pemindahan domain ke `metmalcommunityspace.web.id`

**Tanggal:** 2026-09-18 18:49 WIB
**Cakupan:** dua repo — `medprom-metmal` (API) dan `dashboard-calendar-event`
(komunitas: SPA + API + media R2)
**Status:** kode selesai & ter-push · **deploy terblokir menunggu DNS**

## Tujuan

Mengganti domain `andotherstori.my.id` → `metmalcommunityspace.web.id` pada
seluruh permukaan: CDN media, API medprom, dan API komunitas.

Catatan ejaan: domain terdaftar **`metmalcommunityspace`** (dua huruf "m" di
*community*). Versi tiga-"m" yang sempat ditulis tidak ada di DNS.

## Pemetaan akhir

| Host baru | Origin | Menggantikan |
|---|---|---|
| `cdn.metmalcommunityspace.web.id` | R2 bucket `metmal-gallery` (custom domain) | `cdn.andotherstori.my.id` |
| `promapi.metmalcommunityspace.web.id` | VPS `127.0.0.1:3002` (`medprom-api`) | `promapi.andotherstori.my.id` |
| `api.metmalcommunityspace.web.id` | VPS `127.0.0.1:8080` (`metmal-nginx`) | `metmal.andotherstori.my.id` |

Dua API punya origin **berbeda** — ini mudah tertukar:
`promapi` → 3002 (API medprom saja), `api` → 8080 (nginx komunitas yang
melayani SPA `/` **dan** `/api/v1/*` sekaligus).

## Insiden: migrasi tidak sengaja dijalankan ke produksi

Saat menguji script migrasi di VPS, `--dry-run` **tertelan pembungkus shell**
(`sh -c ... -- --dry-run` diteruskan ke `sh`, bukan ke node), sehingga script
berjalan dalam mode tulis dan mengubah **67 baris** database produksi komunitas
ke domain yang saat itu **NXDOMAIN**. Gambar komunitas sempat tidak tampil.

**Pemulihan** (diverifikasi): 0 baris domain baru · 67 baris domain lama pulih
· 0 gambar rusak di beranda & galeri produksi · URL CDN langsung `HTTP 200`.
Tidak ada data hilang — hanya hostname; objek R2 tidak pernah disentuh.

**Pencegahan:** bawaan script dibalik menjadi lapor-saja. Kegagalan meneruskan
flag kini berakibat "tidak terjadi apa-apa", bukan kerusakan data. Diuji ulang
ke produksi: tanpa flag melaporkan 67 baris, DB tetap 0.

**Pelajaran proses:** jangan menjalankan perintah yang menulis ke database
produksi tanpa memverifikasi flag benar-benar diterima, dan selalu catat
`SELECT` sebelum-sesudah.

## Temuan keamanan: Caddyfile aktif ≠ repo

Caddyfile yang aktif di `/etc/caddy/Caddyfile` ternyata hanya
`reverse_proxy 127.0.0.1:3002` — **tanpa** `header_up X-Real-IP`, tanpa header
keamanan, tanpa log, padahal versi repo memuat semuanya.

Konsekuensi (diverifikasi probe terisolasi): Caddy **meneruskan** `X-Real-IP`
kiriman klien apa adanya (kirim `9.9.9.9` → origin menerima `9.9.9.9`).
`rateLimit.js` memakai header itu sebagai identitas klien, jadi identitas
**spoofable** bila tidak ada proxy di depan yang menimpanya.

- `promapi.*` — aman: Cloudflare menimpa header (terverifikasi: 60× header
  sama → 429; header berbeda → tetap 429).
- `metmal.andotherstori.my.id` — **DNS-only** (langsung ke VPS, tanpa
  Cloudflare), jadi tidak ada yang menimpa → rate limit bisa dilewati.

Tercatat sebagai pitfall #18 di `AGENTS.md` (commit `e0fb288`).

## Blocker

Ketiga host masih **NXDOMAIN**. Deploy sebelum DNS aktif akan memutus gambar
(media) dan API. Karena itu seluruh langkah deploy sengaja belum dijalankan.

## Langkah yang diminta (Cloudflare)

1. **CDN** — Dashboard → R2 → bucket `metmal-gallery` → Settings →
   **Custom Domains** → Connect Domain → `cdn.metmalcommunityspace.web.id`.
   Jangan buat CNAME manual: objek tidak akan tersaji.
2. **`promapi.metmalcommunityspace.web.id`** — A → `43.134.72.148`,
   **Proxied**.
3. **`api.metmalcommunityspace.web.id`** — A → `43.134.72.148`, **Proxied**.

## Rencana deploy (setelah DNS aktif)

Urutan wajib: **API + skema dulu, frontend terakhir** (AGENTS.md pitfall #10).

1. **Caddy** — pasang blok baru (dengan `header_up X-Real-IP`) di
   `/etc/caddy/Caddyfile`, `caddy validate`, lalu `caddy reload`. Sekaligus
   memperbaiki blok lama yang kehilangan `header_up`.
2. **Env VPS** — tidak berubah untuk medprom (CORS_ORIGIN tetap origin Vercel);
   komunitas: pastikan `R2_PUBLIC_URL` di `/opt/metmal/deploy/vps/.env`.
3. **Migrasi data** — `node server/scripts/migrate-cdn-domain.mjs` (lapor),
   verifikasi angka 67, baru `--apply`. Catat jumlah sebelum-sesudah.
4. **Deploy API medprom** — tar over SSH + urutan pitfall #10.
5. **Deploy API komunitas** — idem.
6. **Frontend terakhir** — `VITE_API_URL` baru di Vercel kedua proyek, lalu
   `vercel --prod`.
7. **Verifikasi** — `/healthz` `{db:true}`; track tanpa captcha → 400;
   gambar komunitas tampil dari host baru; `/events/:id` OG benar.
