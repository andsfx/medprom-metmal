# PLAN 2026-11-17 14:47 — Layout landing: kartu kisi katalog di desktop

## Tujuan

User menyatakan secara layout tampilan publik masih kurang pas setelah redesign
Airbnb Rausch. Audit mengikuti skill `redesign-existing-projects` (scan →
diagnose → fix), dibatasi pada **layout**, bukan arah visual (kontrak
`DESIGN.md` tetap: putih + tinta + satu Rausch, Inter).

## Diagnosis (bukti: `docs/landing-2026-11-17-sebelum-desktop.png`, 1280px)

| # | Masalah | Rujukan audit skill |
|---|---|---|
| P0 | Katalog = **satu kolom di semua lebar**. Di desktop baris membentang ~990px; nama dan harga terpisah ratusan piksel, baris terbaca sebagai daftar kerja, bukan marketplace. Tidak ada kehadiran foto (thumbnail 64px). | "Cards… use the space", "Missing whitespace/depth", hierarki marketplace |
| P1 | Judul hero 32px di desktop duduk setara judul bagian — kehadiran display hilang. | "Headlines lack presence" |
| P2 | Kartu kontak: tombol WhatsApp tidak sejajar antar kartu (satu kartu 2 tombol, satu 1); tinggi isi berbeda membuat CTA melayang. | "Buttons not bottom-aligned in card groups" |

Mobile (390px) dinilai sehat sebelum perubahan — baris bergaris, harga tepat di
bawah nama, aksi terlipat satu baris. Struktur ini **dipertahankan**.

## Keputusan

1. **Kartu kisi hanya di `>=640px`, hanya katalog landing.** Alasan: `.ui-row`
   dipakai bersama oleh wizard (pemilih media), riwayat, dan batch — di sana
   baris memang bentuk yang benar (pemilih/daftar, bukan pameran). Kelas
   konteks `.catalog-grid` membatasi efek; 14 kotak berbingkai di layar 6 inci
   tetap ditolak (argumen lama DESIGN.md dipertahankan).
2. **2 kolom di 640–1023px, 3 kolom di >=1024px.** Grid 3 kolom sejak 640px
   membuat kartu ~200px — nama panjang menghimpit harga.
3. **Nama dan harga ditumpuk di dalam kartu** (bukan kiri-kanan seperti baris
   desktop): lebar kartu ~300px tidak cukup untuk "Videotron Integrasia" +
   "Rp. 35.000.000".
4. **Aksi dipatok ke dasar kartu** (`margin-top: auto`) supaya tombol lintas
   kartu sebaris meski isi berbeda (harga bertangga vs tunggal).
5. **Skeleton ikut `.catalog-grid`** agar status memuat berbentuk sama dengan
   hasil akhir (tidak ada lompatan bentuk).
6. Hero: 40px di `>=640px` (satu langkah di atas `--text-screen` 24px).
7. Foto memakai `aspect-ratio: 4 / 3` = ukuran berkas asli 800×600, jadi tidak
   ada pemotongan dan tinggi kartu seragam.

## Rencana langkah

1. CSS: blok `.catalog-grid` + media query hero di `src/styles/base.css`.
2. TSX: kelas `catalog-grid` (kategori + skeleton), `catalog-actions`, kartu
   kontak `flex h-full flex-col` + `mt-auto`, padding hero.
3. Dokumen: `DESIGN.md` (kartu kisi katalog, ukuran hero desktop),
   `CHANGELOG.md` `[Unreleased]`, plan ini.
4. Gate: `tsc`, `build`, `vitest` penuh.
5. Bukti sesudah: screenshot Playwright (route-intercept katalog, bukan file
   repo) desktop 1280 & mobile 390; bandingkan.

## Verifikasi

- **Gate**: `npx tsc --noEmit` 0 galat · `npm run build` hijau · `npx vitest

- **Gaya terhitung (Playwright 1280×900, katalog di-intercept lewat
  `page.route` — bukan file repo)**:
  - `.catalog-grid`: `grid-template-columns` = 3× ~317px, `gap` 16×20px;

- **Keselarasan aksi — hanya DALAM satu baris grid.** Tiga kartu Indoor

- **Ketentuan terbuka (uji interaktif, klik tombol di kartu Videotron)**:

## Risiko & rollback

- **Risiko**: `.catalog-grid .ui-row` menimpa `.ui-row:last-child
  { border-bottom: none }` — aturan kartu memasang `border` penuh dan selektor
  `:last-child` diikutkan eksplisit, jadi kartu terakhir tetap berbingkai.
- **Risiko**: media tanpa `image_path` (sosmed) menjadi kartu tanpa foto;
  konten tetap terbaca karena padding ada di `.ui-row-main`.
- **Rollback**: hapus kelas `catalog-grid`/`catalog-actions` (3 baris TSX) dan
  blok CSS; mobile tidak tersentuh sama sekali.
