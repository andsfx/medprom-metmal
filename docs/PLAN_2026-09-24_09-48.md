## Latar

Layar sukses wizard cetak (`src/components/promo/PromoCetakWizard.tsx` sekitar
baris 445) menampilkan nomor batch dan berkata:

> "Simpan nomor batch ini untuk memantau status seluruh media kapan saja."

Janji itu tidak bisa ditepati. Halaman `/lacak`
(`src/components/promo/TrackSubmissionPage.tsx`) hanya memanggil pelacakan
per-nomor-pengajuan (`fetchStatusByNumber`), dan server menolak format `MPB-`
lewat `SUBMISSION_NUMBER_RE` (`server/src/routes/promo.js`). Akibatnya tenant
yang menyimpan NOMOR BATCH (bukan tautan/token) tidak punya cara melacaknya;
tautan status batch hanya tersedia dari layar sukses dan `/riwayat` di
perangkat yang sama.

## Verifikasi kontrak server (LANGKAH 1, wajib)

Dibaca `server/src/routes/promo.js` pada endpoint pelacakan batch. Tiga
pertanyaan dijawab tegas:

1. **`GET /batches/track` menerima NOMOR BATCH, bukan token.** Handler
   memvalidasi `number` terhadap `BATCH_NUMBER_RE` dan mencari kolom
   `batch_number`:

   ```js
   // server/src/routes/promo.js (sekitar baris 1003-1035)
   const number = normalizeSubmissionNumber(req.query?.number);
   if (!number) return res.status(400).json({ success: false, error: 'Nomor pengajuan wajib diisi.' });
   if (!BATCH_NUMBER_RE.test(number)) {
     return res.status(400).json({
       success: false,
       error: 'Format nomor batch tidak valid. Contoh: MPB-260920-A7K2QX.',
     });
   }
   ...
   const { rows } = await db.query(
     `SELECT id, batch_number, batch_token, applicant_type, applicant_name,
             unit_number, submission_date, notes, created_at
        FROM promo_submission_batches WHERE batch_number = $1 LIMIT 1`,
     [number],
   );
   ```

   dengan `BATCH_NUMBER_RE = /^MPB-\d{6}-[0-9A-Z]{6}$/` (sekitar baris 707).
   Jalur token terpisah dan tetap ada di `GET /batches/status/:token` yang
   mencari `WHERE batch_token = $1`.

2. **Ia MENGEMBALIKAN `batch_token`.** Query di atas memilih kolom
   `batch_token`, lalu handler merangkai bentuk publik lewat `loadBatchDetail`
   dan membalas `{ success: true, data: { batch, items } }`. Jadi respons
   memuat `data.batch.batch_token` yang bisa dipakai mengarahkan ke
   `/batch/<batch_token>`.

3. **Ia MEMERLUKAN captcha Turnstile.** Handler memanggil `verifyTurnstile`
   dengan token dari query `captcha` dan `action: 'track-batch'`:

   ```js
   // server/src/routes/promo.js (sekitar baris 1015-1021)
   const captcha = await verifyTurnstile(req.query?.captcha, {
     remoteip: clientIp(req),
     action: 'track-batch',
   });
   if (!captcha.ok) {
     return res.status(captcha.status || 400).json({ success: false, error: captcha.error });
   }
   ```

   Pola ini sama dengan `fetchStatusByNumber` (`src/utils/promoApi.ts` baris
   245) yang mengirim `captcha` sebagai query untuk `action: 'track'`.

**Kesimpulan: kontrak server SUDAH mendukung pelacakan by nomor batch.** Tidak
ada endpoint server baru dan tidak ada perubahan skema. Karena itu **jalur
implementasi pertama** yang diambil (bukan sekadar menyelaraskan teks layar
sukses).

## Catatan cakupan

- Tidak ada perubahan server, skema, maupun endpoint baru. Kontrak server sudah
  memadai.
- Tautan layar sukses (`PromoCetakWizard.tsx`) TIDAK diubah: setelah perbaikan
  ini janji "simpan nomor batch untuk memantau" sudah bisa ditepati lewat
  `/lacak`.
- Jalur `MP-` dipertahankan utuh, termasuk gerbang captcha dan muat ulang
  setelah revisi.
- **BLOCKER captcha yang SUDAH diperbaiki di putaran ini (commit kedua).**
  Versi pertama putaran ini mengirim `action="track"` untuk KEDUA jalur. Itu
  salah dan menjadikan pelacakan batch selalu gagal begitu captcha diaktifkan:
  - `server/src/routes/promo.js` baris 563 memverifikasi `action: 'track'`
    untuk `GET /submissions/track`, sedangkan baris 1018 memverifikasi
    `action: 'track-batch'` untuk `GET /batches/track`. Keduanya memang sengaja
    berbeda per permukaan.
  - `server/src/lib/turnstile.js` baris 103 menolak bila aksi tidak cocok:
    `const actionMatches = !action || result?.action === action;` lalu baris
    105 `if (!result?.success || !actionMatches || !hostnameAllowed)`.
  - `src/components/ui/Turnstile.tsx` meneruskan prop `action` ke
    `window.turnstile.render({ action, ... })` (baris 92) dan memasang ulang
    widget saat `action` berubah (deps baris 107 `[siteKey, resetKey, action]`),
    memanggil `onToken('')` (baris 84) sehingga token basi tidak terkirim.
  Bug ini tersembunyi selama captcha nonaktif (`verifyTurnstile` mengembalikan
  `{ ok: true, skipped: true }`), itulah sebabnya lolos di putaran pertama.
  Perbaikan: `TrackSubmissionPage.tsx` menurunkan
  `const turnstileAction = number.trim().toUpperCase().startsWith(BATCH_PREFIX) ? 'track-batch' : 'track';`
  dan mengoper `action={turnstileAction}` ke widget. Server TIDAK disentuh.
  Dikunci tiga test baru pada `TrackSubmissionPageBatch.test.tsx` (action
  `track-batch` untuk `MPB-`, `track` untuk `MP-`, dan `track` saat kosong),
  yang MERAH sebelum perbaikan dan HIJAU sesudahnya.
