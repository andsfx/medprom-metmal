Empat temuan yang ditutup keempat commit tersebut:

1. **Cermin `MAX_BATCH_ITEMS` belum terdokumentasi di tabel cermin.** Tabel
   "Cermin FE↔BE yang disengaja" di `AGENTS.md` belum memuat baris batas
   jumlah media batch, padahal commit `414ae35` sudah menguncinya sebagai
   cermin lewat `__tests__/api/cetak-batch-limits.test.js`. Tanpa baris itu,
   agen berikutnya yang mengubah salah satu sisi tidak punya petunjuk bahwa
   pasangannya harus ikut berubah.
2. **Kartu katalog media cetak mengarah ke form yang salah.**
   `PromoLandingPage.tsx` merender kartu untuk SEMUA media aktif dan setiap
   kartu menaut ke `/ajukan` (wizard materi DIGITAL). Tiga media berkanal
   `cetak` (spanduk, big-banner, umbul-umbul) juga muncul di katalog
   Outdoor/Indoor, sehingga kartunya mengarah ke wizard digital yang
   MEWAJIBKAN unggah/tautan materi, padahal alur cetak justru tidak meminta
   berkas (materi menyusul lewat revisi) dan punya form sendiri di
   `/ajukan-cetak` (multi-media + perkiraan PPN 11%). Akibatnya fitur alur
   cetak tidak terjangkau dari katalog, hanya bisa lewat tombol di hero.
3. **Wizard digital masih menerima media cetak, di dua sisi.** FE memanggil
   `fetchMediaTypes()` tanpa argumen kanal sehingga media cetak ikut
   ditawarkan di langkah 1. BE, handler `POST /promo/submit` mencari media
   hanya dengan `slug` + `is_active` tanpa memeriksa kanal, sehingga server
   MENERIMA pengajuan digital untuk media cetak.
4. **Jalur pintas `preselect` melewati filter.** Setelah temuan 3, blok
   `preselect` di `PromoUploadWizard` hanya memeriksa KEBERADAAN slug
   (`rows.some(...)`) lalu langsung `setStep(2)` tanpa memeriksa kanal,
   sehingga membuka `/ajukan?media=spanduk` melompat ke langkah 2 dengan
   media cetak terpilih dan pengguna baru ditolak server di AKHIR form.
   Server memang sudah menangkapnya (tidak gagal senyap), tetapi
   pengalamannya buruk.
