## Keputusan untuk Cacat B: pilihan (b), arahkan ke beranda (`/`)

Dipilih **(b)**: `backTo="/"` pada KEDUA halaman.

Alasan:

1. Tombol kembali harus berperilaku SAMA di setiap cara masuk. Halaman status
   paling sering dibuka LANGSUNG dari tautan/token yang dibagikan (kasus utama
   perangkat lain), dan pada kondisi itu tidak ada riwayat navigasi untuk
   dimundurkan. Kembali-satu-langkah browser (pilihan a) bergantung pada
   riwayat yang tidak ada, sehingga hasilnya tidak dapat diprediksi: pada
   sebagian perangkat tombol tampak tidak bereaksi (no-op), pada sebagian lain
   ia keluar dari aplikasi atau mendarat di halaman yang tidak relevan.
2. Beranda (`/`) selalu ada, tidak menyesatkan, dan memberi jalan lanjut yang
   nyata (katalog, ajukan, lacak nomor), sehingga tenant tidak merasa buntu.
3. Beranda bukan riwayat perangkat, jadi cacat aslinya (tenant mengira
   pengajuannya hilang karena `/riwayat` kosong) hilang sepenuhnya.
4. Perubahan hanya menyentuh prop `backTo` di dua halaman; perilaku tombol
   kembali di layar lain (yang memang punya riwayat navigasi linear, mis.
   wizard dengan `onBack`) tidak ikut berubah.

Teks lain di kedua halaman (termasuk tautan "Lihat Riwayat Perangkat" pada
panel galat/tidak ditemukan) TIDAK diubah, sesuai batasan tugas.

## Rencana

1. Server: tambah paginasi ADITIF pada `GET /promo/submissions/mine` lewat
   query `?offset=<n>`, pertahankan `LIMIT 50` dan pengurutan; sertakan `total`
   dan `offset` pada respons. Tanpa `offset`, bentuk query dan parameter harus
   identik dengan sebelumnya.
2. Klien API (`fetchMySubmissions`): kembalikan `{ rows, total }`; terima juga
   bentuk LAMA (array polos) supaya paginasi tetap aditif; tanpa `offset`, URL
   persis seperti sebelumnya.
3. FE (`MySubmissionsPage`): penanda jujur ("Menampilkan N dari M pengajuan
   terbaru") + tombol "Muat lagi" yang MENAMBAH baris; heuristik halaman penuh
   bila `total` tidak tersedia; cermin batas `MY_SUBMISSIONS_PAGE_SIZE`.
4. FE (`SubmissionStatusPage` + `BatchStatusPage`): `backTo="/"`.
5. Test BARU merah pada kode lama, hijau sesudah; gerbang penuh; dokumentasi.

## Catatan cakupan

- **Aditif murni di server.** Tanpa `?offset`, `offset` bernilai 0 sehingga SQL
  menjadi `LIMIT 50 OFFSET 0` dan parameter tetap `['fp']`; urutan query daftar
  tetap menjadi panggilan `db.query` terakhir supaya
  `__tests__/api/promo-mine-batch.test.js` (yang membaca
  `mock.calls.at(-1)`) tidak berubah. `total` ditambahkan di samping `data`,
  jadi klien lama yang hanya membaca `data` tetap bekerja.
- **`offset` bukan parameter bind.** Nilainya dipaksa integer non-negatif lebih
  dulu, baru diinterpolasi sebagai literal angka; tidak ada jalan masuk SQL
  injection dari query string.
- **Subquery `batch_item_count` dan join batch tidak rusak.** Keduanya tidak
  disentuh selain komentar; subquery tetap TIDAK punya `LIMIT`/`OFFSET`
  sendiri, jadi hitungan item batch tidak ikut terpotong paginasi.
- **`src/components/layout/AppShell.tsx` dan `TopAppBar.tsx` tidak berubah.**
  Percobaan pilihan (a) sempat menyentuhnya; setelah beralih ke pilihan (b)
  keduanya dikembalikan persis seperti HEAD (`git diff` kosong untuk keduanya).
- **Teks lain tidak diubah.** Tautan "Lihat Riwayat Perangkat" pada panel
  galat/tidak ditemukan di kedua halaman status tetap ada.
- **Test lama tidak disentuh.** Semua 65 berkas test lama lulus tanpa
  perubahan; tiga berkas yang meng-mock `fetchMySubmissions` dengan array polos
  tetap hijau karena normalisasi menerima bentuk itu.
- **Tanpa migrasi/skema/endpoint baru**, tanpa dependensi baru, tanpa
  `db:migrate`/`db:seed`, tanpa perubahan `scripts/`.
- **Rollback**: `git revert` commit ini mengembalikan `LIMIT 50` tanpa
  `OFFSET`, respons tanpa `total`, riwayat tanpa tombol "Muat lagi", dan
  tombol kembali ke `/riwayat`. Tidak ada state DB yang perlu dibersihkan.
