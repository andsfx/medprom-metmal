# PLAN 2026-09-24 12:10 WIB - Lokasi pemasangan dari pengajuan pada bukti unggah dan nama pelaku revisi

## Latar cacat

### F1 (utama): lokasi pemasangan selalu 'Belum ditentukan' pada unggah bukti

Berkas `server/src/routes/admin.js`, endpoint
`POST /admin/submissions/:id/installation/proof`, cabang `else` (saat
`promo_installations` belum punya baris) menulis:

```
INSERT INTO promo_installations
  (submission_id, media_location, proof_kind, ...)
VALUES ($1, $2, 'upload', ...)
```

dengan `$2 = sanitize(req.body?.media_location || '', 200) || 'Belum ditentukan'`.

Masalah: `req.body?.media_location` **TIDAK PERNAH terisi**.

- `readMultipartFile` (`server/src/drive.js`) adalah parser multipart streaming
  yang secara eksplisit mengabaikan field non-file (komentar: "Field non-file
  (mis. name) diabaikan").
- FE `uploadInstallationProof` (`src/utils/adminApi.ts`) hanya mengirim field
  `file`.

Jadi `media_location` SELALU jatuh ke literal `'Belum ditentukan'`, padahal
komentar kode menyatakan "lokasi dari pengajuan". Akibatnya baris
`promo_installations` ringkas hasil unggahan bukti kehilangan lokasi
pemasangan yang sebenarnya.

### F2 (kecil): nama pelaku riwayat revisi kosong

Berkas `server/src/routes/promo.js`, endpoint
`POST /promo/submissions/:id/revision`. Panggilan
`insertHistory({ ..., actorType: 'tenant', actorName: '' })` menulis nama
pelaku kosong, padahal jalur tenant lain memakai nama PIC

`promo.js:651` hanya mengambil `id, status, status_token, device_fingerprint,
source_type`, sehingga nama PIC tidak tersedia bagi handler.

## Perubahan

### 1. `server/src/routes/admin.js` - handler `POST /submissions/:id/installation/proof`

**Catatan implementasi (penyimpangan dari instruksi literal, sengaja):**
instruksi meminta *memperluas* SELECT awal (`SELECT id, status FROM
promo_submissions ...`) menjadi juga memuat `media_target`. Namun bentuk SELECT
itu **dikunci oleh test lama** yang menge-mock dengan substring SQL persis:

- `__tests__/api/admin-cetak.test.js:212` dan `:241` memakai
  `text.includes('SELECT id, status FROM promo_submissions')`;
- `__tests__/api/admin-flow.test.js:77,94,148,168,192` juga.

Memperluas literal SELECT membuat substring itu tidak lagi cocok, sehingga mock
jatuh ke `{ rows: [] }` dan handler membalas 404 (dua test lama pecah). Bukti
empiris (lihat bawah). Karena aturan repo melarang menyunting test lama, sumber
lokasi diambil lewat **query kedua** yang SETARA dan tidak mengubah bentuk
SELECT pertama:

```
+    // Lokasi pemasangan diambil dari `media_target` pengajuan - BUKAN dari
+    // `req.body`: `readMultipartFile` (drive.js) sengaja mengabaikan field
+    // non-file, jadi `req.body.media_location` tidak pernah terisi. Query
+    // terpisah (bukan memperluas SELECT di atas) supaya bentuk SELECT di atas
+    // yang dikunci test lama tetap utuh; hasilnya sama.
+    const { rows: locRows } = await db.query(
+      'SELECT media_target FROM promo_submissions WHERE id = $1 LIMIT 1',
+      [id],
+    );
+    existing.media_target = locRows[0]?.media_target || '';
```

Nilai `$2` pada cabang `else` diganti sesuai instruksi (memakai
`existing.media_target`, fallback `'Belum ditentukan'`):

```
-        [id, sanitize(req.body?.media_location || '', 200) || 'Belum ditentukan',
+        [id, sanitize(existing.media_target || '', 200) || 'Belum ditentukan',
```

Komentar cabang `else` diperbarui agar jujur: lokasi diambil dari
`media_target` pengajuan.

Handler sungguhan, pola mock sama dengan `__tests__/api/admin-cetak.test.js`
(mock `db.js`, `drive.js`, `auth.js`, `lib/rateLimit.js`; helper
`getHandler`/`createMockResponse`/`call`). Pengajuan berstatus `sudah_dipasang`
TANPA baris `promo_installations`; mock SELECT pengajuan mengembalikan
`media_target: 'Sisi Pintu Tol Bekasi Barat'`, mock SELECT `promo_installations`
mengembalikan kosong.

   `SELECT media_target FROM promo_submissions ...`);

   dan array parameter **tidak** memuat `'Belum ditentukan'`;
