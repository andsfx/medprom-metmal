- 17/17 route di `server/src/routes/admin.js` memanggil `requireRole` sebaris:
  baca = `READ_ROLES` (submissions, summary, detail, media-types, export),
  tulis = `STAFF_ROLES` (status, installation, delete, CRUD katalog + gambar),
  users = `['superadmin']` (baris 671-759).

### 2. Alur status 8 nilai — DIPERTAHANKAN dengan nuansa

### 3. Drive fail-closed + magic bytes — DIPERTAHANKAN dengan 2 koreksi

- `driveReady` (`server/src/drive.js:32`) + `router.use` 503 (baris 252-255):
  benar untuk router drive. Nuansa: submit mode-upload saat Drive mati ditolak
  lewat `getDriveFile → 400`, bukan 503 — `promo.js:21` tidak mengimpor
  `driveReady`. Kanal tautan tetap hidup (benar).
- `ALLOWED_MIME` global (baris 36-41) + `MIME_MAGIC` + `checkMagicBytes`
  fail-closed (baris 101-115, dipanggil 299-303 sebelum upload): dipertahankan.
- Klaim header "streaming / buffer hanya kepala file" DIBANTAH — pitfall #9
  BENAR: `readMultipartFile` menampung seluruh body di memori (maks 50 MB)
  sebelum ke Drive; `Readable.from(file.chunks)` adalah stream dari buffer
  penuh, bukan passthrough.
- `resolveMaterial` (`promo.js:79-143`) membuang klaim klien mode-upload
  (nama/MIME/ukuran dari metadata Drive): dipertahankan. Pitfall #3
  (`accepted_formats` tidak ditegakkan server): dipertahankan.

### 7. Kritik kelengkapan — 9 permukaan belum tercakup pool

RateLimit spoof (`X-Real-IP` tanpa verifikasi proxy, tanpa `trust proxy`,
bucket in-memory); MID fail-closed setengah jalan (500 generik, tanpa
cache/fallback, URL hardcoded); identifiers (zona waktu YYMMDD, entropi nomor
~30 bit membocorkan volume harian); CSV (tanpa netralisasi formula injection,
memuat PII tanpa `logActivity`, tanpa streaming); fingerprint (opsional saat
submit → lewati batas 5/24 jam, wajib saat revisi padahal mudah dipalsu,
`/mine` mengembalikan `status_token` bermodal itu tanpa rate-limit);
`logActivity` fire-and-forget tanpa await; `backup.sh` tanpa lock/validasi
restore/alerting; Caddyfile tidak berversi padahal `rateLimit` bergantung
`X-Real-IP` darinya; `VITE_*` build-time gagal-diam. Detail +
`file:baris` di `agent://review-7`.

## Risiko + cara rollback

- Risiko perubahan: rendah tetapi **bukan nol** — `device_fingerprint` kini
  wajib, jadi klien lama (cache SW) yang tidak mengirimnya akan ditolak 400.
  Mitigasi: FE selalu mengirim sejak awal; perilaku lama = menerima tanpa batas.
- Rollback: `git revert` berkas server (`admin.js`, `promo.js`) mengembalikan
  perilaku lama tanpa migrasi DB — tidak ada perubahan skema di batch ini.
- Risiko temuan bila dibiarkan: (a) jendela deploy 400 ala pitfall #10 bila
  operator mengikuti README lama; (b) VPS baru gagal `cp .env.example` karena
  exclude glob; (c) keyakinan berlebih pada "200 test hijau" padahal jalur
  401/403 dan 429 tak tereksekusi; (d) CSV formula injection + PII tanpa audit;
  (e) fingerprint sebagai satu-satunya bukti kepemilikan revisi.
