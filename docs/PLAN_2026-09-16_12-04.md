## 1. Tujuan

Menerapkan alur *Tenant Material Management* pada platform media promosi:
pengajuan bermateri (bukan sekadar tautan), 8 status dengan transisi tegas,
nomor pengajuan + token status publik, revisi materi berversi, pencatatan
pemasangan, dan dashboard staf yang bisa mencari/memfilter.

## 2. Keputusan yang Disepakati

| # | Keputusan | Alasan |
|---|---|---|
| 1 | Terapkan PRD penuh, termasuk penataan ulang alur status | Pilihan pengguna |
| 2 | Adopsi 8 status PRD §8 apa adanya | Pilihan pengguna |
| 3 | Kanal **tautan** dan **unggah** sama-sama kelas satu | Pilihan pengguna |
| 4 | Deploy penuh, **kanal tautan lebih dulu** | Pilihan pengguna; kredensial Drive belum ada |
| 5 | `Disetujui → Sudah Dipasang` ditambahkan ke tabel transisi | PRD §8 tidak memuatnya, tetapi FR-040/AC 11.4 menuntut pemasangan dari `disetujui` |

## 3. Rencana Kerja

1. **Fondasi bersama** — modul alur status + pembuat nomor/token, dicerminkan
   di server dan frontend.
2. **Skema** — perluas `promo_submissions`, tambah 3 tabel, remap status lama,
   backfill nomor/token/versi-1.
3. **Server** — rute pengajuan, halaman status token, revisi berversi, rute staf
   (ringkasan, filter, detail, transisi status, pemasangan, ekspor CSV).
4. **Frontend** — wizard PRD §9.3 + dua kanal, halaman `/status/:token`,
   dashboard staf, tautan status di riwayat pengajuan.
5. **Tes** — kontrak FE≡BE, alur status, alur staf, urutan migrasi.
6. **Deploy** — kirim kode → terapkan skema → seed → restart API → frontend.

## 5. Perbaikan Selama Pengerjaan

1. **Migrasi gagal di DB berjalan** — remap berjalan sebelum CHECK lama dilepas.
   Diperbaiki dengan urutan lepas → remap → tambah, dan penargetan constraint
   berbasis definisi (nama constraint berbeda antar versi skema).
2. **`submissionWaLink` memakai status lama** — akan mengirim kunci mentah
   seperti `disetujui` ke tenant. Kini memakai `STATUS_LABELS`.
3. **`users.role` default `viewer`** melanggar CHECK-nya sendiri.
4. **`GOOGLE_*` wajib di compose** — akan memblokir boot API tanpa kredensial
   Drive. Diubah opsional (`:-`), kanal unggah tetap fail-closed (`503`).
5. **`rsync --delete` menghapus backup** — kedua perintah di
   `deploy/vps/README-DEPLOY.md` kini memuat `--exclude 'backups/'`.

## 6. Risiko & Rollback

- **Kode & skema harus naik bersamaan.** Di antara migrasi dan restart API,
  pengajuan baru gagal `400` (`violates check constraint`) sementara `/healthz`
  tetap `ok` karena tidak menyentuh DB. Urutan aman: kode → `stop api` → skema →
  `up -d`.
- **Backup pra-rilis**: `/opt/medprom/backups/pre-v1.3.0-migration-20260916-113845.sql.gz`
- **Rollback kode**: `/root/medprom-code-1.0.0-20260916-113419.tar.gz`
- **Rollback DB**: `gunzip -c <backup> | docker compose exec postgres psql -U medprom -d medprom`
  (dari `/opt/medprom/deploy/vps`).
