# Pelacakan Pengajuan via Nomor + Captcha Turnstile

Tanggal: 2026-09-18 15:49 WIB · Status: selesai

## Tujuan

Tenant yang kehilangan tautan status (`/status/:token`) tidak punya jalan lain
untuk memantau pengajuannya — nomor pengajuan `MP-YYMMDD-XXXXXX` sudah dibuat
"mudah dibacakan" tetapi belum bisa dipakai apa pun. Tambahkan jalur kedua:
**input nomor pengajuan → lihat status yang sama**. Karena nomor mudah ditebak
polanya (`MP-` + tanggal + 6 karakter acak), endpoint baru ini digerbangi
**captcha Cloudflare Turnstile** — keputusan pemilik produk: nomor boleh
diakses publik, tetapi tidak boleh dipanen otomatis.

## Keputusan yang disepakati

- **Nomor bukan rahasia.** Tidak ada verifikasi tambahan (tidak ada pertanyaan
  keamanan, tidak ada pencocokan telepon). Captcha adalah satu-satunya gerbang.
- **Captcha: Cloudflare Turnstile** — dipilih karena tanpa dependensi npm
  (kebijakan repo): widget dimuat lewat `<script>` dan verifikasi server cukup
  `fetch` ke Siteverify. Alternatif captcha mandiri (HMAC) ditolak karena tidak
  menyaring bot canggih.
- **Envelope & isi identik dengan halaman token.** Kedua jalur memakai komponen
  server yang sama (`loadSubmissionDetail`) dan komponen React yang sama
  (`SubmissionDetail`), supaya tidak ada dua definisi "status pengajuan".
- **Fail-closed** bila Siteverify tak terjangkau (503), dan **dilewati dengan
  peringatan boot** bila `TURNSTILE_SECRET_KEY` kosong — supaya instance lama
  tetap jalan, tetapi gerbangnya harus dinyalakan sebelum dipakai publik.

## Rencana langkah

1. Server: `GET /promo/submissions/track?number=&captcha=` + `lib/turnstile.js`.
2. FE: `fetchStatusByNumber`, halaman `/lacak`, widget Turnstile, tautan masuk.
3. Test: helper Turnstile, endpoint track, komponen, client API.
4. Dokumentasi: README, AGENTS, CHANGELOG.
5. Gate: `node --check`, `npx vitest run`, `npm run build`, CRLF=0.

## Perbaikan selama pengerjaan

- **Token Turnstile sekali pakai** — widget semula tidak dipasang ulang setelah
  dipakai, sehingga pencarian kedua pasti ditolak Siteverify
  (`timeout-or-duplicate`) dan muat ulang setelah revisi selalu gagal.
  Diperbaiki: widget menerima `resetKey`, token dibuang tiap pengiriman, dan
  muat ulang menahan nomor di `pendingReload` sampai token segar tersedia.
  Dikunci `src/components/ui/__tests__/Turnstile.test.tsx` + satu test halaman.
- **`verifyTurnstile` awal memakai pola `if (fingerprint)`-style guard** — diperbaiki
  jadi fail-closed eksplisit: gangguan jaringan → 503, bukan lolos.
- **`TURNSTILE_SECRET_KEY` tidak diteruskan `docker-compose.yml`** — compose
  mendaftar env satu per satu; tanpa baris ini secret di `.env` VPS tidak sampai
  ke container sehingga captcha diam-diam nonaktif. Sudah ditambahkan (`:-`).
- Test komponen sempat menulis `import.meta.env` langsung (gagal type-check karena
  `ImportMeta.env` tidak dideklarasikan di tsconfig test) → diganti `vi.stubEnv`.
- `import('pkg').Type` dan fungsi satu-baris dihindari (aturan repo).

## Risiko + cara rollback

- **Risiko:** endpoint publik baru mengembalikan data pengajuan kepada siapa pun
  yang tahu nomornya. Diterima pemilik produk. Captcha + rate limit 60/15 mnt
  membatasi panen massal; kolom internal (fingerprint/IP) tetap tidak di-SELECT.
- **Risiko:** bila secret key lupa diisi di produksi, captcha dilewati (hanya
  peringatan log). Mitigasi: peringatan boot eksplisit + didokumentasikan di
  README/AGENTS.
- **Rollback:** hapus rute `track` + tautan FE; tidak ada perubahan skema, tidak
  ada migrasi. `SubmissionDetail` tetap dipakai halaman token.

## Penyempurnaan kontrak kanonik Turnstile (2026-09-18)

Setelah mengikuti alur resmi Cloudflare (`spin/prompt.md`), verifikasi awal yang
hanya mengecek `success` dinaikkan ke kontrak kanonik penuh:

- **`action`** — widget `/lacak` memasang `action="track"`, server menuntut
  kecocokan; token sah dari permukaan lain tidak bisa dipakai ulang di sini.
- **`hostname`** — dicocokkan terhadap allowlist `TURNSTILE_HOSTNAMES`. Secret
  terisi tanpa allowlist → verifikasi **ditolak 503** (fail-closed), bukan
  dilewati; produksi tidak boleh memuat `localhost`/`127.0.0.1`.
- **Batas panjang token** 2048 karakter (spesifikasi Cloudflare) ditolak lokal
  tanpa memanggil Siteverify.
- **Content-Type** Siteverify dipindah ke `application/x-www-form-urlencoded`
  (bentuk kanonik; JSON juga diterima Cloudflare, tetapi form adalah acuan).
- Env baru `TURNSTILE_HOSTNAMES` diteruskan `docker-compose.yml` + didokumentasikan
  (`.env.example`, `deploy/vps/.env.example`, README, AGENTS pitfall #15/#16).
- Suite penuh naik ke **32 berkas / 279 test**.

Catatan: alur *retrieve secret via Wrangler* dari `spin/prompt.md` tidak
dijalankan — secret sudah diberikan pemilik produk, disimpan di `.env` yang
terverifikasi `git check-ignore` (diabaikan git), dan divalidasi ke Siteverify
(dummy token → `invalid-input-response` = secret valid).
