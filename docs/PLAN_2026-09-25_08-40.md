# PLAN 2026-09-25 08:40 (WIB) - Alur pemilihan media cetak

## Laporan pemilik

> "workflow nya masih membingungkan, harusnya ketika pilih media cetak,
> langsung menuju pilihan tenant atau non tenant. Bukan langsung ke Step 2"

## Diagnosis

`PromoCetakWizard.tsx` punya tiga langkah: **1 Data Pemohon** (pilih
Tenant/Non-tenant), **2 Pilih Media & Periode**, **3 Ringkasan & Kirim**.
Berbeda dari wizard digital (`PromoUploadWizard.tsx`) yang langkah 1-nya justru
Pilih Media, sehingga pra-pilih media di sana wajar melompat ke langkah 2.

Pada wizard cetak, efek pemuatan katalog memanggil `setStep(2)` ketika query
param `?media=<slug>` cocok dengan katalog cetak:

```ts
if (preselect && rows.some((m) => m.slug === preselect)) {
  setItems([buatBaris(preselect)]);
  setStep(2);            // <-- melompati langkah Data Pemohon
}
```

Akibatnya, membuka `/ajukan-cetak?media=spanduk` (dari kartu cetak di landing)
langsung mendarat di langkah Pilih Media tanpa pemohon ditentukan. Ini keliru:
langkah 1 adalah prasyarat (jenis pemohon menentukan field yang wajib diisi).

## Perbaikan

Hapus `setStep(2)`. Media dari katalog tetap ditandai terpilih lebih awal
(`setItems([buatBaris(preselect)])`), sehingga saat staf menekan "Lanjut ke
Pilih Media" setelah mengisi data pemohon, media itu sudah tercentang.

Langkah Data Pemohon juga menampilkan penanda "Media terpilih: Spanduk. Bisa
diubah di langkah Pilih Media." bila `items.length > 0`, supaya pengguna yang
mengklik kartu media di landing tidak mengira pilihannya hilang saat mendarat
di langkah pemohon. Penanda ini hanya informasi; alur dan jumlah langkah tidak
berubah.

## Bukti dua arah

Test baru `src/components/promo/__tests__/PromoCetakWizardPreselect.test.tsx`
(5 test):

1. `?media=spanduk` mendarat di langkah Data Pemohon, bukan Pilih Media;
2. media dari katalog tetap tercentang saat langkah Pilih Media dibuka;
3. tanpa `?media=` tetap mulai dari langkah Data Pemohon;
4. langkah Data Pemohon menampilkan penanda "Media terpilih: Spanduk";
5. tanpa media terpilih, penanda tidak ditampilkan.

Dijalankan terhadap kode SEBELUM perbaikan: **2 test merah** untuk kontrak
pendaratan (bukti menangkap bug). Sesudah perbaikan: **5 test hijau**.

## Dampak ke skrip verifikasi

`scripts/verify-cetak.mjs` masuk lewat CTA "Ajukan Media Cetak" tanpa `?media=`
(lalu mengisi langkah 1 secara eksplisit), sehingga tidak terpengaruh. Tidak ada
selektor atau teks yang diubah; skrip verifikasi tidak disentuh.

## Catatan

Ini bagian dari alur yang sama dengan `PromoCetakWizard` multi-media; tidak ada
perubahan server, skema, maupun cermin harga.

## Temuan sampingan 1: kredensial login memang sudah publik (sesuai permintaan)

Pemilik meminta kredensial admin terlihat di publik selama pengembangan. Ini
SUDAH terpasang: `src/components/admin/AdminLoginPage.tsx` merender panel
"Akun demo (tahap pengembangan)" berisi tiga akun staf dan password bersama
`admin123`, digerbangi `isDevLoginHintEnabled()` di
`src/constants/devCredentials.ts` yang menyala secara bawaan (opt-out lewat
`VITE_PROMO_SHOW_DEV_LOGIN='0'`). Env itu tidak diset di produksi, sehingga
panel benar-benar tampil di `/login` produksi (diverifikasi live). Sudah
dikunci `AdminLoginPage.test.tsx`. Tidak ada perubahan diperlukan.

## Temuan sampingan 2: service worker tidak menyapu cache aset shell (diperbaiki)

Pemilik masih melihat lompatan ke langkah 2 meski kode sudah mendarat di
langkah 1. Investigasi menemukan bahwa `public/sw.js` (service worker) TIDAK
bertanggung jawab atas HTML (navigasi bersifat network-first), tetapi ada cacat
terkait: commit `077de87` mengganti ikon PWA tanpa menaikkan `CACHE_VERSION`,
melanggar aturan #2 SW sendiri, sehingga aset shell lama tersaji tanpa batas.
`CACHE_VERSION` dinaikkan `v11` ke `v12`; dikunci
`__tests__/service-worker-shell.test.js`.

Untuk keluhan langkah 2 sendiri: verifikasi pada konteks browser bersih +
hard-reload menunjukkan `/ajukan-cetak?media=spanduk` mendarat di
**LANGKAH 1 DARI 3 - DATA PEMOHON** di produksi, sementara
`/ajukan?media=videotron` (jalur digital, by-design) mendarat di LANGKAH 2.
Jadi fix sudah live; bila perangkat tertentu masih menampilkan langkah 2, itu
sisa service worker lama dari deploy sebelum `13a6736`/`8c53897`. Pembersihan:
DevTools > Application > Service Workers > Unregister, atau mode incognito.
